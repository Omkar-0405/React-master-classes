1. What is Routing?

Routing decides which UI should be displayed for a given URL.

URL ↓ Router ↓ Match route ↓ Render route element ↓ Page / Layout

In a client-side React application, the router can update the UI without requesting a completely new HTML document for every navigation.

2. React Router

React Router provides routing primitives for React applications, including route matching, navigation, nested routes, URL parameters and data APIs.

import {
  createBrowserRouter,
  RouterProvider
} from "react-router-dom";

const router = createBrowserRouter([
  {
    path: "/",
    element: <Home />
  },
  {
    path: "/about",
    element: <About />
  }
]);

createRoot(document.getElementById("root")).render(
  <RouterProvider router={router} />
);

3. Routes and Route Matching

A route maps a URL pattern to UI and optionally to data-loading/error-handling behavior.

const router = createBrowserRouter([
  {
    path: "/users/:userId",
    element: <User />
  }
]);

When the browser navigates to /users/42, the :userId parameter matches 42.

4. Nested Routes

Nested routes let child routes render inside a parent route layout.

const router = createBrowserRouter([
  {
    path: "/dashboard",
    element: <DashboardLayout />,
    children: [
      {
        index: true,
        element: <DashboardHome />
      },
      {
        path: "settings",
        element: <Settings />
      },
      {
        path: "users",
        element: <Users />
      }
    ]
  }
]);

Notice that child paths such as settings are relative to the parent.

5. Outlet

Outlet is the placeholder where the currently matched child route renders.

import { Outlet, NavLink } from "react-router-dom";

function DashboardLayout() {
  return (
    <div>
      <nav>
        <NavLink to="/dashboard">Home</NavLink>
        <NavLink to="/dashboard/settings">Settings</NavLink>
      </nav>

      <main>
        <Outlet />
      </main>
    </div>
  );
}
/dashboard ↓ DashboardLayout ↓ <Outlet /> ↓ DashboardHome /dashboard/settings ↓ DashboardLayout ↓ <Outlet /> ↓ Settings

6. URL Params

Route params represent dynamic path segments.

Route:
"/products/:productId"

URL:
"/products/123"
import { useParams } from "react-router-dom";

function Product() {
  const { productId } = useParams();

  return <h1>Product {productId}</h1>;
}

Params are useful when the resource identity is part of the path.

Params vs Search Params

Route ParamsSearch Params
/products/123/products?category=books
Usually identifies a resource.Usually represents filtering, sorting, pagination or optional UI state.
Defined in route pattern.Comes after ?.

7. Search Params

Search/query parameters are values after ?.

URL:
"/products?category=books&page=2"
import { useSearchParams } from "react-router-dom";

function Products() {
  const [searchParams, setSearchParams] =
    useSearchParams();

  const category = searchParams.get("category");
  const page = searchParams.get("page");

  return (
    <button
      onClick={() => {
        setSearchParams({
          category: "electronics",
          page: "1"
        });
      }}
    >
      {category} - page {page}
    </button>
  );
}

Search params are strings, so convert them when you need numbers/booleans.

8. Navigation

Use router navigation APIs instead of manually changing window.location for normal client-side navigation.

import {
  Link,
  useNavigate
} from "react-router-dom";

function Home() {
  const navigate = useNavigate();

  return (
    <>
      <Link to="/about">About</Link>

      <button onClick={() => navigate("/dashboard")}>
        Dashboard
      </button>
    </>
  );
}

9. Lazy Routes

Lazy routes allow route modules to be loaded only when the route is needed.

const router = createBrowserRouter([
  {
    path: "/",
    element: <Layout />,
    children: [
      {
        path: "dashboard",
        lazy: async () => {
          const module = await import("./routes/dashboard");
          return {
            Component: module.Component
          };
        }
      }
    ]
  }
]);

This can reduce the initial JavaScript required for routes that users may never visit.

10. React.lazy vs Route lazy

React.lazyReact Router lazy route
Lazy-loads a React component.Lazy-loads route module implementations.
Usually paired with Suspense.Integrated with React Router's route/data APIs.
Useful for individual components.Useful for route-level code splitting.

11. Loaders

A React Router loader lets a route define data that should be loaded for that route.

const router = createBrowserRouter([
  {
    path: "/users/:userId",
    loader: async ({ params }) => {
      const response = await fetch(
        `/api/users/${params.userId}`
      );

      if (!response.ok) {
        throw new Response("User not found", {
          status: response.status
        });
      }

      return response.json();
    },
    element: <User />
  }
]);

The route component can read the loaded data with useLoaderData().

12. useLoaderData

import { useLoaderData } from "react-router-dom";

function User() {
  const user = useLoaderData();

  return <h1>{user.name}</h1>;
}

The loader and route component are connected through the router's data APIs.

13. Loader vs useEffect Fetch

Route LoaderuseEffect Fetch
Route-level data API.Component-level synchronization.
Can load data as part of navigation.Component first renders, then effect runs.
Works with router navigation/data APIs.Useful for effects tied to component lifecycle.

Choose based on whether the data is fundamentally part of route loading or component synchronization.

14. Protected Routes

A protected route allows access only when the user satisfies an authentication/authorization condition.

function ProtectedRoute({ children }) {
  const user = useAuth();

  if (!user) {
    return <Navigate to="/login" replace />;
  }

  return children;
}

This is a UI/navigation guard. The backend must still enforce authorization.

15. Protected Routes with a Layout

function RequireAuth() {
  const user = useAuth();

  if (!user) {
    return <Navigate to="/login" replace />;
  }

  return <Outlet />;
}

const router = createBrowserRouter([
  {
    element: <RequireAuth />,
    children: [
      {
        path: "/dashboard",
        element: <Dashboard />
      },
      {
        path: "/settings",
        element: <Settings />
      }
    ]
  }
]);

One guard can protect multiple routes.

16. Authentication vs Authorization

AuthenticationAuthorization
Who are you?What are you allowed to access?
Login/session/token identity.Roles, permissions, resource access.
Example: user is logged in.Example: only admins can access /admin.
Security rule: A frontend protected route is not a security boundary. APIs must enforce authorization on the server.

17. Role-Based Protected Route

function RequireAdmin() {
  const user = useAuth();

  if (!user) {
    return <Navigate to="/login" replace />;
  }

  if (user.role !== "admin") {
    return <Navigate to="/forbidden" replace />;
  }

  return <Outlet />;
}

This improves UX, but the server must also check the user's permissions.

18. 404 / Not Found Route

const router = createBrowserRouter([
  {
    path: "*",
    element: <NotFound />
  }
]);

A catch-all route can render a friendly not-found page when no more specific route matches.

19. Route Error Handling

Data routers support route-level error handling. A route can provide an error element/component to show fallback UI when its loader/action or descendant route encounters a handled routing error.

const router = createBrowserRouter([
  {
    path: "/users/:id",
    loader: loadUser,
    element: <User />,
    errorElement: <RouteError />
  }
]);

20. Complete Routing Mental Model

URL changes ↓ Router matches route tree ↓ Nested layouts selected ↓ Loaders run (if configured) ↓ Route components render ↓ <Outlet /> renders child route ↓ Protected checks / redirects ↓ Page displayed

Most Asked Interview Questions

  1. What is React Router? A routing library/toolset for matching URLs to React UI and managing navigation and route data.
  2. What are nested routes? Child routes rendered within a parent route/layout.
  3. What is Outlet? The placeholder where a matched child route renders.
  4. What are route params? Dynamic values embedded in a path, such as /users/:id.
  5. What are search params? Query values after ?, such as ?page=2.
  6. Params vs search params? Params commonly identify a resource; search params commonly represent filters, sorting, pagination or optional state.
  7. How do you navigate programmatically? Use useNavigate or router navigation APIs.
  8. What is lazy routing? Loading route code only when the route is needed.
  9. Why lazy-load routes? To reduce the initial JavaScript bundle.
  10. What is a loader? A route-level data-loading function used by React Router's data APIs.
  11. Loader vs useEffect? A loader is integrated with route navigation/data loading; useEffect is component-level synchronization.
  12. What is a protected route? A route that redirects or blocks UI access when authentication/authorization requirements are not met.
  13. Is a protected React route secure? No. Server-side authorization is still required.
  14. Authentication vs authorization? Authentication identifies the user; authorization determines what the user is allowed to do.
  15. How do you protect multiple routes? Use a parent guard/layout that renders an Outlet for authorized child routes.
  16. How do you implement a 404? Add a catch-all route such as *.
  17. Why use replace when redirecting to login? It can prevent the protected URL from remaining as an unwanted history entry.

Scenario-Based Questions

  1. /dashboard/settings should share the dashboard sidebar.
    Use nested routes with a DashboardLayout and Outlet.
  2. You need the current user ID from /users/42.
    Define /users/:userId and read it with useParams.
  3. You need /products?category=books&page=2.
    Use search params with useSearchParams.
  4. A filter should survive page refresh.
    Store it in the URL search params rather than only local component state.
  5. An admin page is rarely visited.
    Lazy-load the admin route to reduce the initial bundle.
  6. You need user data before rendering a route.
    Consider a route loader if the data is naturally part of route navigation.
  7. A user navigates to /dashboard while logged out.
    Redirect to /login with a protected route/guard.
  8. A logged-in user opens /admin but lacks the admin role.
    Redirect to a forbidden/unauthorized page and enforce the same permission on the server.
  9. Every protected route repeats the same auth check.
    Use a parent protected layout with Outlet.
  10. An unknown URL should show a custom page.
    Add a catch-all * route.
  11. A loader fails because a user does not exist.
    Throw/return an appropriate response/error and show route-level error UI.
  12. A component fetches data that is unrelated to route entry.
    useEffect or a server-state library may be more appropriate than a route loader.
  13. You want to navigate after saving a form.
    Use useNavigate or the appropriate router navigation API after the save succeeds.
  14. You want a link that behaves like normal SPA navigation.
    Use Link/NavLink instead of manually changing window.location.
  15. You need to preserve the current filter while navigating pages.
    Keep the filter in search params and update the URL intentionally during navigation.
