What is Hoisting?

Hoisting means JavaScript moves declarations to the top of their scope before execution. Only declarations are hoisted, not the assignments.

Execution Order

JS Starts │ Create Memory │ Hoist Variables & Functions │ Execute Code Line by Line

var Hoisting

console.log(a);
var a = 10;

Memory Phase:

a → undefined

Output:

undefined

Reason: var gets memory first and is initialized with undefined.

let Hoisting

console.log(age);
let age = 20;
ReferenceError

let is hoisted but remains uninitialized until its declaration.

const Hoisting

console.log(PI);
const PI = 3.14;
ReferenceError

const behaves like let but must also be initialized when declared.

Temporal Dead Zone (TDZ)

TDZ is the time between memory creation and variable initialization.

Memory Created │ ▼ TDZ Begins │ let x; │ TDZ Ends

Function Declaration Hoisting

greet();

function greet(){
 console.log("Hello");
}

Hello

Entire function is hoisted.

Function Expression

sayHi();

var sayHi = function(){
 console.log("Hi");
}

TypeError: sayHi is not a function

Only the variable is hoisted as undefined.

Arrow Function

hello();

const hello = () => {
 console.log("Hello");
}

ReferenceError

Arrow functions follow the hoisting rules of the variable they are assigned to.

Why does var become undefined?

During the memory creation phase, JavaScript allocates memory for var variables and automatically initializes them with undefined. The assignment happens later during execution.

Difference: Function Declaration vs Function Expression

Can call before declarationCannot call before assignment
Safer for reusable functionsUseful for callbacks
