1. Why TypeScript with React?

TypeScript adds static type checking to JavaScript. It catches many mistakes during development before the application runs.

TypeScript ↓ Check types ↓ Compile / transform ↓ JavaScript ↓ Browser

In React, TypeScript is especially useful for props, events, refs, API data, hooks and reusable components.

Interview idea: TypeScript does not replace runtime validation. Data coming from an API is still untrusted at runtime.

2. Props Interface

An interface can describe the props a component expects.

interface ButtonProps {
  label: string;
  disabled?: boolean;
  onClick: () => void;
}

function Button({
  label,
  disabled = false,
  onClick
}: ButtonProps) {
  return (
    <button
      disabled={disabled}
      onClick={onClick}
    >
      {label}
    </button>
  );
}

? makes a property optional. You can also use a type alias instead of an interface.

Interface vs Type

interfacetype
Common for object shapes and public contracts.Can represent objects plus unions, tuples, primitives and more.
Can be extended and declaration-merged.Supports composition through intersections/unions.
Both can type React props.Choice often depends on team style and use case.

3. Children Typing

import type { ReactNode } from "react";

interface CardProps {
  title: string;
  children: ReactNode;
}

function Card({
  title,
  children
}: CardProps) {
  return (
    <section>
      <h2>{title}</h2>
      {children}
    </section>
  );
}

ReactNode is useful when children may contain strings, elements, fragments, numbers and other renderable React content.

4. Generic Components

Generics allow a component to work with different types while preserving type safety.

interface ListProps<T> {
  items: T[];
  renderItem: (item: T) => React.ReactNode;
}

function List<T>({
  items,
  renderItem
}: ListProps<T>) {
  return (
    <ul>
      {items.map((item, index) => (
        <li key={index}>
          {renderItem(item)}
        </li>
      ))}
    </ul>
  );
}
<List
  items={[1, 2, 3]}
  renderItem={n => <span>{n * 2}</span>}
/>

<List
  items={["React", "TypeScript"]}
  renderItem={name => <span>{name}</span>}
/>

The same component works with different item types without losing type information.

5. Generic Component with Key Selection

interface TableProps<T> {
  data: T[];
  getKey: (item: T) => string | number;
}

function Table<T>({
  data,
  getKey
}: TableProps<T>) {
  return (
    <div>
      {data.map(item => (
        <div key={getKey(item)}>
          {JSON.stringify(item)}
        </div>
      ))}
    </div>
  );
}

Generics are especially useful for reusable tables, selects, lists, forms and data-driven components.

6. Utility Types

TypeScript utility types transform existing types instead of making you repeat them.

interface User {
  id: number;
  name: string;
  email: string;
  role: "admin" | "user";
}

type UserUpdate = Partial<User>;
type UserPreview = Pick<User, "id" | "name">;
type UserWithoutId = Omit<User, "id">;
type ReadonlyUser = Readonly<User>;

Common Utility Types

UtilityMeaning
Partial<T>All properties become optional.
Required<T>All properties become required.
Readonly<T>Properties cannot be reassigned through that type.
Pick<T, K>Select specific properties.
Omit<T, K>Remove specific properties.
Record<K, T>Creates an object type with keys K and values T.
ReturnType<F>Gets a function's return type.
Parameters<F>Gets a function's parameter tuple.

7. Union Types

A union means a value can be one of several types or literal values.

type Status =
  | "idle"
  | "loading"
  | "success"
  | "error";

function StatusText({
  status
}: {
  status: Status;
}) {
  return <p>{status}</p>;
}

Literal unions are very useful for component variants, status values and restricted props.

Union with Props

type ButtonProps =
  | {
      variant: "link";
      href: string;
    }
  | {
      variant: "button";
      onClick: () => void;
    };

This can express that a link needs href, while a button needs onClick.

8. Type Guards

A type guard helps TypeScript narrow a broad type to a more specific type.

function isString(
  value: unknown
): value is string {
  return typeof value === "string";
}

function print(value: unknown) {
  if (isString(value)) {
    console.log(value.toUpperCase());
  }
}

Discriminated Union

type Result =
  | { status: "success"; data: User }
  | { status: "error"; message: string };

function View({ result }: { result: Result }) {
  if (result.status === "success") {
    return <p>{result.data.name}</p>;
  }

  return <p>{result.message}</p>;
}

The status property acts as the discriminator, allowing TypeScript to narrow the object safely.

9. React.FC

React.FC<Props> is a type for React function components.

import type { FC } from "react";

interface Props {
  name: string;
}

const Welcome: FC<Props> = ({ name }) => {
  return <h1>Hello {name}</h1>;
};

Modern React code does not require React.FC. Many teams prefer typing the props directly on the function because it is simpler and explicit.

React.FC — Interview Point

function Welcome({ name }: Props) {
  return <h1>Hello {name}</h1>;
}

This direct style is often preferred. It makes the function's props obvious and avoids treating FC as necessary for every component.

10. Event Types

React provides event types for common DOM interactions.

function Input() {
  const handleChange = (
    event: React.ChangeEvent<HTMLInputElement>
  ) => {
    console.log(event.target.value);
  };

  return (
    <input onChange={handleChange} />
  );
}

11. Refs

Use useRef when you need a stable mutable reference that does not cause a re-render when its current value changes.

const inputRef =
  useRef<HTMLInputElement | null>(null);

function focusInput() {
  inputRef.current?.focus();
}

return (
  <>
    <input ref={inputRef} />
    <button onClick={focusInput}>
      Focus
    </button>
  </>
);

useRef — DOM vs Mutable Value

const timerRef =
  useRef<ReturnType<typeof setTimeout> | null>(null);

const countRef = useRef(0);

countRef.current += 1;

Changing ref.current does not trigger a render. Use state when a value must update the UI.

12. Custom Hooks Typing

Custom hooks should expose clear input and output types.

function useToggle(
  initial = false
): [boolean, () => void] {
  const [value, setValue] =
    useState(initial);

  const toggle = () =>
    setValue(v => !v);

  return [value, toggle];
}

The return type makes the hook contract explicit.

Generic Custom Hook

function useFetch<T>(
  url: string
): {
  data: T | null;
  loading: boolean;
  error: Error | null;
} {
  // implementation
  return {
    data: null,
    loading: true,
    error: null
  };
}

const result = useFetch<User>("/api/user");

Generics let one hook support different response types while preserving type safety.

13. API Data Typing

TypeScript types do not validate JSON at runtime.

interface User {
  id: number;
  name: string;
}

const user: User =
  await response.json();

This tells TypeScript what you expect, but the server could still return invalid data. Use runtime validation when the boundary requires strong guarantees.

14. Generic API Response

interface ApiResponse<T> {
  data: T;
  message: string;
}

async function getUser(): Promise<ApiResponse<User>> {
  const response = await fetch("/api/user");
  return response.json();
}

This avoids duplicating the response wrapper type for every API resource.

interface SearchProps {

function Search({

  return (
    <input
      onChange={e =>

Type callbacks by their input and return values.

16. Generic Select Component

interface SelectProps<T> {
  options: T[];
  value: T;
  getLabel: (item: T) => string;
  onChange: (item: T) => void;
}

function Select<T>({
  options,
  value,
  getLabel,
  onChange
}: SelectProps<T>) {
  return (
    <select
      value={getLabel(value)}
      onChange={e => {
        const item = options.find(
          x => getLabel(x) === e.target.value
        );

        if (item) onChange(item);
      }}
    >
      {options.map(item => (
        <option key={getLabel(item)}>
          {getLabel(item)}
        </option>
      ))}
    </select>
  );
}

In production, use a stable ID/value rather than relying on labels as unique identifiers.

17. Type Narrowing in React

function ErrorMessage({
  error
}: {
  error: unknown;
}) {
  if (error instanceof Error) {
    return <p>{error.message}</p>;
  }

  return <p>Something went wrong</p>;
}

Using unknown instead of any forces you to narrow the value before using it unsafely.

19. TypeScript Best Practices in React

  • Type component props explicitly.
  • Prefer narrow types over any.
  • Use discriminated unions for state machines.
  • Use generics for truly reusable data-driven components.
  • Type DOM events using React's event types.
  • Type refs with the actual DOM element or value type.
  • Keep custom hook contracts clear.
  • Remember that TypeScript types disappear at runtime.
  • Validate untrusted API data when necessary.

Most Asked Interview Questions

  1. Why use TypeScript with React? It catches many type errors during development and makes component/API contracts clearer.
  2. How do you type React props? Define an interface/type and use it as the function parameter type.
  3. Interface vs type? Both can type props; interfaces are object-oriented/extensible contracts, while type aliases are more flexible for unions and compositions.
  4. What are generics? A way to write reusable code while preserving the relationship between input and output types.
  5. Why use generic components? To build reusable components that work with many data types without losing type safety.
  6. What is Partial? It makes all properties of a type optional.
  7. Pick vs Omit? Pick selects properties; Omit removes properties.
  8. What is a union type? A type that allows one of several alternatives.
  9. What is a discriminated union? A union whose members share a literal discriminator that lets TypeScript narrow the member safely.
  10. What is a type guard? A runtime check that provides information TypeScript uses to narrow a type.
  11. What is React.FC? A function-component type. It is optional; direct props typing is often simpler.
  12. How do you type an input event? Usually with React.ChangeEvent<HTMLInputElement>.
  13. How do you type a form submit? Use React.FormEvent<HTMLFormElement>.
  14. How do you type a DOM ref? For example, useRef<HTMLInputElement | null>(null).
  15. Does changing ref.current re-render? No.
  16. How do you type a custom hook? Explicitly type its parameters and return value when that improves clarity.
  17. Can TypeScript validate API JSON? Not by itself at runtime. Type declarations are erased; runtime validation needs actual validation code/library.
  18. Why use unknown instead of any? unknown requires narrowing before unsafe operations and therefore preserves more type safety.

Scenario-Based Questions

  1. A Button component accepts label, disabled and onClick.
    Create a Props interface/type with string, optional boolean and callback types.
  2. A component must render strings, numbers or React elements as children.
    Use ReactNode for the children prop.
  3. You are building a reusable table for User and Product objects.
    Use a generic Table<T> so the table preserves the row type.
  4. A component can be either a link or a button.
    Use a discriminated union so each variant requires its correct props.
  5. An API response can be success or error.
    Model it as a discriminated union with a status field and narrow before accessing variant-specific properties.
  6. An API returns unknown JSON.
    Do not blindly trust the TypeScript interface; validate the runtime data if correctness/security requires it.
  7. A ref points to an input element.
    Use useRef<HTMLInputElement | null>.
  8. A ref stores a timeout ID.
    Type the ref according to the project's runtime environment, for example ReturnType<typeof setTimeout> | null.
  9. You need to update only part of a User object.
    Use Partial<User> for a patch/update type when appropriate.
  10. You need a public user DTO without email.
    Use Omit<User, "email"> or define a dedicated DTO if the contract is important.
  11. A reusable hook fetches different resource types.
    Make the hook generic, such as useFetch<T>.
  12. A hook returns state and an action.
    Define a tuple or object return type so consumers know the contract.
  13. An event handler receives an unknown error.
    Use unknown and narrow with instanceof Error or another type guard.
  14. A developer uses any for every API response.
    Replace it with proper types and runtime validation at the API boundary where necessary.
  15. React.FC is used everywhere by a team.
    It is valid, but explain that it is not required and direct props typing is often simpler.
