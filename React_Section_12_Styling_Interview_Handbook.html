Section 12 — React Styling

Simple Interview Handbook • CSS Modules • Tailwind • Styled Components • Emotion • MUI • Chakra UI • Ant Design • Theme Provider

1. Why Styling Strategy Matters

React does not force one styling solution. A project can use plain CSS, CSS Modules, utility classes, CSS-in-JS, or a component library.

Component ↓ Choose styling approach ↓ Styles + tokens + responsive rules ↓ Browser CSS ↓ UI
Interview idea: Choose based on maintainability, team familiarity, design-system needs, bundle/runtime cost, accessibility and project requirements.

2. CSS Modules

CSS Modules scopes CSS class names to a component/module so names are less likely to collide globally.

/* Button.module.css */
.button {
  padding: 8px 16px;
}

.primary {
  background: blue;
}
import styles from "./Button.module.css";

function Button() {
  return (
    <button className={`${styles.button} ${styles.primary}`}>
      Save
    </button>
  );
}

The build system transforms local class names into unique generated names.

CSS Modules — Advantages

  • Local class-name scope.
  • Normal CSS syntax.
  • Good separation between JSX and styling.
  • Easy to adopt in existing CSS-based applications.

Tradeoff: You still manage CSS files, naming and design tokens yourself.

3. Tailwind CSS

Tailwind CSS is a utility-first CSS framework. Instead of creating many custom classes, you compose small utility classes directly in markup.

function Button() {
  return (
    <button className="
      px-4 py-2
      rounded
      bg-blue-600
      text-white
      hover:bg-blue-700
    ">
      Save
    </button>
  );
}

The build process generates/ships the CSS needed by the project's utilities according to the configured setup.

Tailwind — Advantages & Tradeoffs

AdvantagesTradeoffs
Fast consistent styling.JSX can become class-heavy.
Design tokens/utilities.Requires learning utility vocabulary.
Responsive utilities are convenient.Complex repeated patterns need component abstractions.

4. Styled Components

styled-components is a CSS-in-JS library where styles are defined using JavaScript template literals and attached to components.

import styled from "styled-components";

const Button = styled.button`
  padding: 8px 16px;
  border-radius: 6px;
  background: ${props =>
    props.primary ? "blue" : "gray"};
  color: white;
`;

function App() {
  return <Button primary>Save</Button>;
}

Styles can react to component props and theme values.

5. Emotion

Emotion is another CSS-in-JS library. It supports styled APIs and CSS composition.

import styled from "@emotion/styled";

const Card = styled.div`
  padding: 16px;
  border-radius: 8px;
  background: white;
`;

function App() {
  return <Card>Hello</Card>;
}

Emotion is commonly used directly or as part of other UI-library styling systems.

CSS-in-JS — Interview Concept

Component props/theme ↓ CSS-in-JS styles ↓ Generated/scoped CSS ↓ Browser

Depending on the library/version/configuration, styles may involve runtime work, build-time extraction, or both. Do not claim all CSS-in-JS libraries work exactly the same way.

6. Material UI (MUI)

Material UI is a React component library based on Material Design concepts, with components, theming, responsive utilities and customization APIs.

import Button from "@mui/material/Button";

function App() {
  return (
    <Button variant="contained">
      Save
    </Button>
  );
}

It is useful when you need many ready-made accessible UI components and a themeable design system.

MUI Theming

import { createTheme, ThemeProvider } from "@mui/material/styles";

const theme = createTheme({
  palette: {
    primary: {
      main: "#1976d2"
    }
  }
});

function App() {
  return (
    <ThemeProvider theme={theme}>
      <AppContent />
    </ThemeProvider>
  );
}

7. Chakra UI

Chakra UI provides accessible React components and a style-system approach for building interfaces quickly.

import { Button } from "@chakra-ui/react";

function App() {
  return <Button colorPalette="blue">Save</Button>;
}

Exact APIs vary by Chakra UI version, so check the project's installed version when coding.

8. Ant Design

Ant Design is a comprehensive React UI library with components commonly used in enterprise applications.

import { Button } from "antd";

function App() {
  return <Button type="primary">Save</Button>;
}

It includes many complex components such as tables, forms, date pickers and modals.

9. Theme Provider

A Theme Provider makes shared design values available to components, such as colors, spacing, typography and breakpoints.

ThemeProvider ↓ theme ┌───┼────┬──────┐ colors spacing type breakpoints ↓ Components ↓ Consistent UI
const theme = {
  colors: {
    primary: "#2563eb",
    danger: "#dc2626"
  },
  spacing: {
    sm: 8,
    md: 16
  }
};

The exact implementation depends on the styling system.

10. Theme Provider Example with styled-components

import {
  ThemeProvider
} from "styled-components";

const theme = {
  colors: {
    primary: "#2563eb"
  }
};

function App() {
  return (
    <ThemeProvider theme={theme}>
      <Dashboard />
    </ThemeProvider>
  );
}
const Button = styled.button`
  background: ${({ theme }) =>
    theme.colors.primary};
`;

11. Dark Mode

A theme system makes dark/light themes easier to manage consistently.

const lightTheme = {
  colors: {
    background: "#ffffff",
    text: "#111827"
  }
};

const darkTheme = {
  colors: {
    background: "#111827",
    text: "#ffffff"
  }
};
Theme state ↓ Select light / dark theme ↓ ThemeProvider ↓ All themed components ↓ Consistent colors

12. Design Tokens

Design tokens are shared values that represent the design system.

const tokens = {
  colors: {
    primary: "#2563eb",
    success: "#16a34a"
  },
  spacing: {
    xs: 4,
    sm: 8,
    md: 16,
    lg: 24
  },
  radius: {
    sm: 4,
    md: 8
  }
};

Tokens reduce random one-off values and make global design changes easier.

13. Responsive Styling

Responsive design adapts UI to different viewport sizes.

/* CSS */
.card {
  padding: 16px;
}

@media (min-width: 768px) {
  .card {
    padding: 24px;
  }
}

Tailwind, MUI, Chakra and other systems provide their own responsive APIs on top of CSS capabilities.

15. Avoid Mixing Randomly

A project can technically use multiple styling systems, but doing so without a plan increases complexity.

❌ Component A → Tailwind ❌ Component B → MUI ❌ Component C → Emotion ❌ Component D → random CSS Possible result: Different tokens Different spacing Different patterns More maintenance

Choose a primary approach and define clear exceptions when another system is necessary.

16. Accessibility

Styling is not only visual. Components should maintain readable contrast, keyboard accessibility, visible focus states and semantic HTML.

<button className="button">
  Save
</button>

<div
  role="button"
  tabIndex="0"
>
  Avoid this unless necessary
</div>

Prefer native semantic elements such as button, input and label when possible.

17. Performance Considerations

  • Avoid unnecessary large CSS payloads.
  • Use production build optimizations.
  • Code split large component libraries/features where appropriate.
  • Keep selectors and component styling manageable.
  • Measure actual performance before optimizing.

Do not assume a particular styling solution is always faster; implementation and build configuration matter.

Most Asked Interview Questions

  1. What are CSS Modules? CSS files whose class names are scoped locally by the build system.
  2. Why use CSS Modules? To avoid global class-name collisions while keeping normal CSS.
  3. What is Tailwind? A utility-first CSS framework for composing styles from utility classes.
  4. What is CSS-in-JS? A family of approaches where styles are represented/managed through JavaScript, often with component-aware APIs.
  5. Styled Components vs Emotion? Both provide CSS-in-JS approaches and styled APIs; exact runtime/build behavior depends on their versions/configuration.
  6. What is Material UI? A React component library with Material Design foundations and a theming/customization system.
  7. What is Chakra UI? A React component library with accessible components and a style-system approach.
  8. What is Ant Design? A comprehensive React UI component library often used for enterprise applications.
  9. What is a ThemeProvider? A provider that makes shared theme/design values available to descendants.
  10. What are design tokens? Shared design values such as colors, spacing, typography and radii.
  11. CSS Modules vs Tailwind? CSS Modules provide scoped custom CSS; Tailwind provides utility classes for composing styles.
  12. When would you choose a UI library? When ready-made components, accessibility patterns, consistency and development speed are valuable.
  13. Can you use multiple styling systems? Yes, but uncontrolled mixing increases complexity and inconsistent design patterns.
  14. How do you implement dark mode? Use theme tokens/provider or CSS variables/class-based theme switching and apply consistent semantic colors.
  15. Does CSS-in-JS always have runtime cost? No single answer; libraries differ in runtime, extraction and build behavior.
  16. How do you make styling accessible? Use semantic HTML, sufficient contrast, visible focus states, keyboard support and accessible component behavior.

Scenario-Based Questions

  1. Class names from two components are colliding.
    Use CSS Modules or another scoped styling strategy.
  2. The team wants rapid utility-based responsive styling.
    Tailwind can be a good fit if the team accepts its utility-first approach.
  3. You need a complete enterprise UI with tables/forms/dialogs.
    MUI or Ant Design may reduce implementation time, depending on the desired design system.
  4. You need a custom design system with shared colors and spacing.
    Define design tokens and expose them through a theme system.
  5. The application needs light and dark modes.
    Use semantic theme tokens and switch the active theme rather than hardcoding colors throughout components.
  6. A styled component needs different colors based on props.
    CSS-in-JS systems such as styled-components/Emotion can derive styles from props.
  7. A large application uses MUI but one team wants Tailwind everywhere.
    Agree on a primary design system and define clear boundaries before introducing a second system.
  8. A button looks clickable but cannot be used with a keyboard.
    Use a semantic button and ensure focus/keyboard behavior rather than styling a generic div.
  9. Dark mode has dozens of hardcoded colors.
    Replace them with semantic theme tokens.
  10. The app has inconsistent spacing: 13px here, 17px there, 23px elsewhere.
    Introduce spacing tokens and reusable layout patterns.
  11. A component library makes the initial bundle larger.
    Analyze imports/bundle output, use supported tree-shaking/code splitting and load large features only when needed.
  12. Two styling systems are causing duplicate theme values.
    Centralize design tokens and reduce overlapping styling infrastructure.
  13. You need responsive cards on mobile and desktop.
    Use CSS media queries or the responsive APIs of the chosen styling system.
  14. A developer says Tailwind eliminates the need to understand CSS.
    Incorrect. Understanding CSS layout, cascade, specificity, responsive design and accessibility is still important.
  15. A developer says MUI is always better than CSS Modules.
    There is no universal winner; a component library and scoped CSS solve different problems.
