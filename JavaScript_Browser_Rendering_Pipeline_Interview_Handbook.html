Browser Rendering Pipeline

Simple Interview Handbook • DOM → CSSOM → Render Tree → Layout → Paint → Composite

What is the Rendering Pipeline?

The browser turns HTML, CSS and other resources into the pixels you see on screen.

HTML + CSS ↓ DOM + CSSOM ↓ Render Tree ↓ Layout ↓ Paint ↓ Composite ↓ Screen

Interview shortcut: Structure → Style → What is visible → Position/size → Pixels → Layers.

1. DOM — Document Object Model

The browser parses HTML and creates a tree of nodes called the DOM.

<body>
  <h1>Hello</h1>
  <p>World</p>
</body>
Document │ └── body ├── h1 └── p

JavaScript can read and modify this tree.

document.querySelector("h1").textContent = "Hi";

2. CSSOM — CSS Object Model

The browser parses CSS and builds a CSSOM: a tree representing CSS rules and their computed relationships.

h1 { color: red; }
p  { font-size: 16px; }

The browser uses CSS rules to determine how DOM elements should look.

3. Render Tree

The browser combines DOM and CSS information to determine what should actually be rendered.

DOM + CSSOM │ ▼ Render Tree │ ├── visible elements └── visual styles

Not every DOM node appears in the render tree. For example, an element with display:none does not participate in rendering.

4. Layout

Layout calculates the size and position of rendered elements.

width: 300px;
padding: 20px;
margin: 10px;
Where? ↓ x, y position width height relationships with other elements

Layout is also called reflow.

5. Paint

Paint converts the visual parts into drawing operations: text, colors, borders, shadows, images, etc.

Layout information ↓ Paint ↓ Text + colors + borders + images + shadows

Changing a background color often requires paint but may not require a new layout.

6. Composite

The browser combines painted layers into the final image shown on the screen.

Layer A ─┐ Layer B ─┼──► Composite ──► Screen Layer C ─┘

Some properties, such as transform and opacity, can often be handled efficiently during compositing when the element is on an appropriate composited layer.

Complete Pipeline

1. HTML ↓ 2. DOM ↓ 3. CSS ↓ 4. CSSOM ↓ 5. DOM + CSSOM ↓ 6. Render Tree ↓ 7. Layout / Reflow ↓ 8. Paint ↓ 9. Composite ↓ 10. Pixels on screen

What Causes Layout?

Changes that affect geometry can trigger layout.

element.style.width = "500px";
element.style.height = "200px";
element.style.margin = "20px";

Because the browser may need to recalculate positions and sizes.

What Causes Paint?

Visual changes that do not change geometry may only require paint.

element.style.backgroundColor = "red";
element.style.color = "white";

Why transform and opacity are Popular for Animation

.box {
  transform: translateX(100px);
  opacity: 0.5;
}

These properties can often avoid repeated layout work and may allow the browser to update a composited layer efficiently.

Important: This is not a guarantee. Actual behavior depends on the browser, element, layer promotion and surrounding rendering conditions.

Forced Synchronous Layout

A common performance problem happens when JavaScript changes styles and then immediately asks for layout information.

element.style.width = "500px";

console.log(element.offsetWidth);

The browser may need to calculate layout immediately before returning offsetWidth.

This is often called forced synchronous layout or layout thrashing when repeated in a read/write pattern.

React Connection

React does not replace the browser rendering pipeline. React updates the DOM; the browser still performs its normal rendering work.

React state update ↓ React render ↓ DOM update ↓ Browser rendering pipeline ↓ Layout → Paint → Composite

Unnecessary DOM changes can therefore lead to unnecessary browser rendering work.

Most Asked Interview Questions

  1. What is the rendering pipeline? The process of converting page structure and styles into pixels.
  2. What is DOM? A tree representation of HTML.
  3. What is CSSOM? The browser's object representation of CSS rules.
  4. What is the Render Tree? The visual structure built from DOM and CSS information.
  5. Does every DOM element appear in the Render Tree? No. For example, display:none elements do not participate in rendering.
  6. What happens during Layout? The browser calculates element size and position.
  7. What is reflow? Recalculation of layout after geometry changes.
  8. What happens during Paint? The browser creates drawing operations for visual content.
  9. What is compositing? Combining painted layers into the final screen image.
  10. Why can transform be better for animation? It can often avoid layout and be handled efficiently by compositing.
  11. What is layout thrashing? Repeatedly forcing layout through alternating DOM writes and layout reads.
  12. Does React control Paint and Composite? No. React updates the DOM; the browser handles rendering.

Scenario-Based Questions

  1. You change an element's width repeatedly during animation.
    This can trigger repeated layout. Prefer transform-based animation when appropriate.
  2. You change only background color.
    Usually this needs paint, not layout.
  3. You animate translateX.
    It can often be handled efficiently during compositing.
  4. You change width and then immediately read offsetWidth.
    The browser may perform synchronous layout.
  5. A page has many unnecessary DOM updates.
    Reduce DOM work and batch related updates.
  6. An element uses display:none and you cannot see it.
    It does not participate in the normal render tree while hidden this way.
  7. A React component re-renders frequently.
    Check whether it causes unnecessary DOM changes and expensive browser rendering work.
  8. A box-shadow changes but its size does not.
    It generally affects paint rather than geometry.
  9. You need a smooth UI animation.
    Prefer compositor-friendly properties such as transform and opacity when suitable.
  10. You see layout thrashing in a performance profile.
    Separate DOM reads from writes and avoid forcing layout repeatedly.
  11. You modify a class that changes width, padding and color.
    Geometry changes can trigger layout; visual changes can also require paint.
  12. You want to understand why a page feels slow while scrolling.
    Use browser DevTools Performance tools to inspect scripting, layout, paint and compositing work.
