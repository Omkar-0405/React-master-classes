1. Same-Origin Policy

The Same-Origin Policy (SOP) is a browser security rule that restricts how a page from one origin can interact with resources from another origin.

Origin = Protocol + Host + Port https://example.com:443 │ │ │ protocol host port

Two URLs have the same origin only when protocol, host and port all match.

URL AURL BSame Origin?
https://app.comhttps://app.com/usersYes
https://app.comhttp://app.comNo
https://app.comhttps://api.app.comNo
https://app.com:443https://app.com:3000No

2. What is CORS?

CORS (Cross-Origin Resource Sharing) is a browser mechanism that allows a server to declare which cross-origin requests a browser may allow a web page to make.

Frontend https://app.com │ │ cross-origin request ▼ API https://api.com │ │ CORS response headers ▼ Browser decides whether JS gets response

CORS is primarily enforced by browsers. Server-to-server requests are not blocked by browser CORS rules.

3. Simple Request

Some cross-origin requests can be sent without a CORS preflight. The browser still checks the server's CORS response before exposing the response to JavaScript.

fetch("https://api.example.com/users");

For a permitted request, the server may return:

Access-Control-Allow-Origin: https://app.example.com

4. Preflight Request

A preflight is a browser-generated request sent before certain cross-origin requests to ask the server whether the actual request is allowed.

Browser │ │ OPTIONS /users │ Origin: https://app.com │ Access-Control-Request-Method: PUT │ Access-Control-Request-Headers: Authorization ▼ Server │ │ Permission headers ▼ Browser │ │ actual PUT ▼ Server

Preflight commonly occurs for requests that are not CORS-safelisted, such as certain methods or custom/request headers.

5. OPTIONS Method

OPTIONS asks what communication options are available for a resource. Browsers use it for CORS preflight.

OPTIONS /users HTTP/1.1
Origin: https://app.com
Access-Control-Request-Method: PUT
Access-Control-Request-Headers: Authorization

A server can respond with headers such as:

Access-Control-Allow-Origin: https://app.com
Access-Control-Allow-Methods: GET, POST, PUT
Access-Control-Allow-Headers: Authorization, Content-Type

6. Common CORS Headers

HeaderPurpose
Access-Control-Allow-OriginAllowed origin(s).
Access-Control-Allow-MethodsAllowed methods for a preflighted request.
Access-Control-Allow-HeadersAllowed request headers.
Access-Control-Allow-CredentialsAllows credentials for cross-origin requests when the request also opts in.
Access-Control-Max-AgeHow long a preflight result may be cached.

7. Credentials & CORS

fetch("https://api.example.com/user", {
  credentials: "include"
});

When credentials are included, the server must explicitly allow credentials and cannot use * as the allowed origin.

Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Credentials: true

8. HTTP Methods

MethodTypical Use
GETRead/fetch a resource.
POSTCreate a resource or trigger an operation.
PUTReplace the representation of a resource.

OPTIONSAsk about supported communication options; used for CORS preflight.

GET

Used to retrieve data. It should not intentionally change server state.

GET /users/42

GET requests are commonly cacheable and are intended to be safe.

POST

Often used to create a resource or submit data for processing.

POST /users
Content-Type: application/json

{"name":"Omkar"}

PUT vs PATCH

PUT /users/42
{"name":"Omkar","email":"new@example.com"}

PUT commonly represents replacement of a resource representation.

PATCH /users/42
{"email":"new@example.com"}

PATCH is intended for partial modifications.

DELETE

DELETE /users/42

Requests deletion of a resource.

React / Frontend Connection

fetch("https://api.example.com/users", {
  method: "POST",
  headers: {
    "Content-Type": "application/json"
  },

The browser may perform a CORS preflight depending on the request. Your backend must return the appropriate CORS headers.

Most Asked Interview Questions

  1. What is Same-Origin Policy? A browser security rule restricting cross-origin web interactions.
  2. What is CORS? A browser mechanism for controlled cross-origin resource sharing.
  3. What is an origin? Scheme/protocol + host + port.
  4. What is a preflight request? A browser OPTIONS request that checks whether a cross-origin request is permitted.
  5. Why is OPTIONS used? It asks the server about supported communication options and is used for CORS preflight.
  6. Does every cross-origin request trigger preflight? No. Some requests are CORS-safelisted.
  7. Can CORS be fixed only from React? No. The server must provide appropriate CORS headers.
  8. GET vs POST? GET retrieves; POST commonly creates/submits data.
  9. PUT vs PATCH? PUT commonly replaces; PATCH partially modifies.
  10. 401 vs 403? 401 relates to authentication; 403 means access is forbidden.
  11. 404 vs 500? 404 means resource not found; 500 indicates an internal server error.
  12. What is 429? Too Many Requests, usually indicating rate limiting.

Scenario-Based Questions

  1. React calls another domain and the browser reports a CORS error.
    Configure the API server's CORS policy; frontend code alone cannot grant permission.
  2. A PUT request sends Authorization and triggers OPTIONS.
    This is likely a CORS preflight because the request is not safelisted.
  3. Backend supports GET but frontend sends DELETE.
    Ensure DELETE is allowed by the API and, for CORS, included in Access-Control-Allow-Methods.
  4. OPTIONS returns 204 before the actual request.
    That can be a successful preflight response; the browser may then send the actual request.
  5. You need to create a new user.
    Typically use POST.
  6. You want to replace a user's complete resource.
    Typically use PUT.
  7. You want to update only the email.
    Typically use PATCH.
  8. You want to retrieve a user.
    Use GET.
  9. You want to delete a user.
    Use DELETE.
  10. API returns 401.
    Check authentication credentials/token rather than treating it as a permission-only error.
  11. API returns 403.
    The request is understood but access is not allowed; check authorization/permissions.
  12. API returns 503.
    The service is currently unavailable; retry strategy and server health may be relevant.
