Section 9 — React Forms

Simple Interview Handbook • Controlled • Uncontrolled • Validation • Form Libraries • Dynamic & Schema-driven Forms

1. What is Form State?

Form state includes values, errors, touched fields, dirty state, submission state and other information needed to manage a form.

User types ↓ Form state changes ↓ Validate ↓ Show errors / update UI ↓ Submit valid data ↓ API
Interview idea: The main choice is whether the browser DOM or React/form library is the primary source of truth for field values.

2. Controlled Components

In a controlled component, React state is the source of truth for the input value.

function Login() {
  const [email, setEmail] = useState("");

  return (
    <input
      value={email}
      onChange={e => setEmail(e.target.value)}
    />
  );
}
Input ↓ onChange React state ↓ value prop ↓ Input

This gives React direct control over the current field value.

Controlled — Advantages

  • Easy to validate as the user types.
  • Easy to conditionally enable/disable UI.
  • React always knows the current value.
  • Easy to derive UI from form state.

Tradeoff: Large forms can produce many state updates and renders if not designed carefully.

3. Uncontrolled Components

In an uncontrolled form, the DOM keeps the current input value. React reads it when needed, commonly through a ref.

function Login() {
  const emailRef = useRef(null);

  function submit(e) {
    e.preventDefault();
    console.log(emailRef.current.value);
  }

  return (
    <form onSubmit={submit}>
      <input ref={emailRef} />
      <button>Submit</button>
    </form>
  );
}

Controlled vs Uncontrolled

ControlledUncontrolled
React state is source of truth.DOM is source of truth.
Uses value + onChange.Often uses defaultValue + ref/FormData.
Easy live validation/UI logic.Can be simpler for basic forms.
More React updates.Less state wiring.

4. Form Validation

Validation checks whether submitted/input data satisfies business and data rules.

function validate(values) {
  const errors = {};

  if (!values.email) {
    errors.email = "Email is required";
  } else if (!values.email.includes("@")) {
    errors.email = "Enter a valid email";
  }

  if (!values.password) {
    errors.password = "Password is required";
  }

  return errors;
}

Validation can happen on change, blur, submit, or a combination.

Client vs Server Validation

Client ValidationServer Validation
Fast feedback.Authoritative validation.
Improves user experience.Protects business rules and data integrity.
Can be bypassed.Must always be trusted as the final validation layer.
Never rely only on client-side validation for security or business-critical rules.

Validation Timing

  • onChange: immediate feedback, but can be noisy.
  • onBlur: validate after the user leaves a field.
  • onSubmit: simple and common for final validation.
  • Hybrid: use different strategies for different fields.

5. Formik

Formik is a React form library that provides form state, handlers, validation support and submission helpers.

function LoginForm() {
  return (
    <Formik
      initialValues={{ email: "" }}
      onSubmit={values => {
        console.log(values);
      }}
    >
      {({ values, handleChange, handleSubmit }) => (
        <form onSubmit={handleSubmit}>
          <input
            name="email"
            value={values.email}
            onChange={handleChange}
          />
          <button type="submit">Submit</button>
        </form>
      )}
    </Formik>
  );
}

Formik is familiar in many existing React codebases, though teams should evaluate current ecosystem and performance needs before choosing it for new work.

Formik — Common Concepts

ConceptMeaning
valuesCurrent form values.
errorsValidation errors.
touchedFields the user has interacted with.
handleChangeUpdates field values.
handleBlurTracks field blur.
handleSubmitRuns submission logic.

6. React Hook Form

React Hook Form (RHF) is a form library designed around uncontrolled/native inputs by default, refs and subscriptions. It can reduce unnecessary re-renders for large forms.

function LoginForm() {
  const {
    register,
    handleSubmit,
    formState: { errors }
  } = useForm();

  const onSubmit = data => {
    console.log(data);
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input
        {...register("email", {
          required: "Email is required"
        })}
      />

      {errors.email && (
        <p>{errors.email.message}</p>
      )}

      <button>Submit</button>
    </form>
  );
}

React Hook Form — register

register connects an input to React Hook Form.

<input
  {...register("username", {
    required: true,
    minLength: 3
  })}
/>

It provides the necessary ref, name and event handlers.

React Hook Form — Controller

Some third-party controlled components do not expose a normal input interface. RHF's Controller can bridge them.

<Controller
  name="country"
  control={control}
  render={({ field }) => (
    <Select
      value={field.value}
      onChange={field.onChange}
    />
  )}
/>

7. Final Form

Final Form is a framework-agnostic form state management library. React Final Form provides React bindings.

const form = createForm({
  onSubmit: values => {
    console.log(values);
  }
});

It uses subscriptions so components can subscribe to only the parts of form state they need.

Performance idea: field-level subscriptions can reduce unnecessary updates in large forms.

Formik vs React Hook Form vs Final Form

FormikReact Hook FormFinal Form
State/handler abstraction around forms.Uncontrolled-first, ref/subscription-oriented.Subscription-based form state.
Easy to understand.Often efficient for large forms.Fine-grained subscriptions.
Common in existing apps.Strong ecosystem and validation integrations.React Final Form is the React binding.

8. Dynamic Forms

A dynamic form changes its fields based on user choices or data.

function Form({ type }) {
  return (
    <>
      <input name="name" />

      {type === "company" && (
        <input name="companyName" />
      )}

      {type === "student" && (
        <input name="college" />
      )}
    </>
  );
}

Dynamic forms commonly need dynamic validation, default values and cleanup of values from fields that are removed.

Dynamic Field Arrays

const { fields, append, remove } = useFieldArray({
  control,
  name: "skills"
});

return (
  <>
    {fields.map((field, index) => (
      <div key={field.id}>
        <input {...register(`skills.${index}.name`)} />
        <button type="button" onClick={() => remove(index)}>
          Remove
        </button>
      </div>
    ))}

    <button type="button" onClick={() => append({ name: "" })}>
      Add
    </button>
  </>
);

Use stable field IDs provided by the form library rather than using array indexes as React keys when the rows can change.

9. Schema-Driven Forms

A schema-driven form stores field definitions in configuration/data and uses a generic renderer to generate the form.

const schema = [
  {
    name: "firstName",
    type: "text",
    label: "First Name",
    required: true
  },
  {
    name: "department",
    type: "select",
    label: "Department",
    options: ["Engineering", "HR"]
  }
];
Form Schema ↓ Generic Form Renderer ↓ Field Components ┌────┼────┐ Text Select Checkbox ↓ Validation ↓ Submit normalized data

Schema-Driven Architecture

const fieldMap = {
  text: TextField,
  select: SelectField,
  checkbox: CheckboxField
};

function DynamicForm({ schema }) {
  return (
    <form>
      {schema.map(field => {
        const Field = fieldMap[field.type];

        return (
          <Field
            key={field.name}
            {...field}
          />
        );
      })}
    </form>
  );
}

The schema describes what the form needs; reusable field components decide how each field is rendered.

Schema-Driven Validation

Validation rules can also be represented in the schema.

{
  name: "email",
  type: "email",
  label: "Email",
  validation: {
    required: true
  }
}

For complex systems, a validation library such as Zod, Yup or another schema validator can be integrated. The backend must still validate submitted data.

Controlled vs Library Performance

Controlled form Input → React state → parent/form renders Uncontrolled-first form Input → DOM/ref ↓ targeted subscriptions ↓ affected UI only

This is one reason React Hook Form and subscription-oriented libraries can perform well on large forms. Actual performance still depends on component design.

Form Best Practices

  • Give every field a clear name.
  • Use labels and accessible error messages.
  • Do not rely only on client validation.
  • Keep validation rules close to the field/schema when appropriate.
  • Handle loading/submitting state to prevent duplicate submissions.
  • Normalize data before sending it to APIs.
  • For large forms, avoid unnecessary whole-form re-renders.
  • Use stable keys for dynamic field arrays.

Most Asked Interview Questions

  1. Controlled vs uncontrolled components? Controlled inputs use React state as the source of truth; uncontrolled inputs keep their value in the DOM.
  2. When would you use controlled inputs? When the UI needs immediate access to and control over field values.
  3. When are uncontrolled inputs useful? For simpler forms or when avoiding large amounts of React state wiring is useful.
  4. What is form validation? Checking that form data satisfies required format and business rules.
  5. Client vs server validation? Client validation improves UX; server validation is authoritative and mandatory for security/data integrity.
  6. What is Formik? A React form library for managing values, errors, touched state and submission.
  7. What is React Hook Form? A form library using an uncontrolled/ref-oriented model and subscriptions to manage forms efficiently.
  8. What is register in RHF? It connects a native-like input to React Hook Form.
  9. What is Controller in RHF? A bridge for controlled/third-party inputs that do not integrate directly with register.
  10. What is Final Form? A form state management library with subscription-based updates; React Final Form provides React bindings.
  11. Which form library is fastest? There is no universal answer; benchmark the actual form. RHF and subscription-oriented designs can reduce unnecessary renders.
  12. What is a dynamic form? A form whose fields or rules change based on user choices or configuration.
  13. What is a schema-driven form? A generic form renderer that generates fields from a configuration/schema.
  14. How do you handle dynamic field arrays? Use stable field identifiers and update/validate array data consistently.
  15. How do you prevent duplicate submissions? Track submitting state, disable the submit action while processing and make the backend handle idempotency where appropriate.
  16. Why is server validation still needed? Client-side checks can be bypassed and cannot be trusted for security.

Scenario-Based Questions

  1. You need to show a password-strength indicator while typing.
    A controlled field or form-library subscription is appropriate because the UI needs the current value.
  2. You have a simple contact form with three fields.
    Plain controlled inputs may be enough; a library is not mandatory.
  3. You have a 50-field enterprise form.
    Consider React Hook Form or Final Form and design subscriptions carefully to avoid unnecessary re-renders.
  4. A third-party Select component does not expose a normal input ref.
    Use React Hook Form Controller or the equivalent integration for your chosen library.
  5. An email field should show an error after the user leaves it.
    Use onBlur validation or the form library's touched/blur mechanism.
  6. You need to validate all fields before submitting.
    Run schema/form validation during submit and stop the API request when errors exist.
  7. A company field should appear only when accountType is company.
    Conditionally render the field and decide explicitly whether its hidden value should be removed or retained.
  8. A user can add unlimited phone numbers.
    Use a field-array pattern with stable IDs and array validation.
  9. A dynamic field is removed but its old value is still submitted.
    Configure the form to unregister/remove the field value or explicitly normalize the submitted data.
  10. You need 30 different forms with the same field types.
    Consider a schema-driven renderer with reusable field components.
  11. Backend changes the form definition based on user role.
    Fetch/receive a validated schema, map supported field types to trusted components, and render it dynamically.
  12. You want arbitrary component names from the server to execute in the browser.
    Do not dynamically execute untrusted code. Use a safe allowlist mapping of schema types to known components.
  13. Client validation says the amount is valid but the server rejects it.
    Show the server validation error; server rules are authoritative.
  14. The submit button is clicked five times quickly.
    Disable it while submitting and handle duplicate requests safely on the server where needed.
  15. A form has expensive validation on every keystroke.
    Validate on blur/submit or debounce suitable validation rather than doing expensive work on every change.

  • ✔ React Hook Form = uncontrolled/ref/subscription-oriented.
  • ✔ Controller = integrate controlled third-party inputs.
  • ✔ Final Form = subscription-based form state.
  • ✔ Dynamic form = fields change based on data/user choices.
  • ✔ Schema-driven = schema → generic renderer → fields.
