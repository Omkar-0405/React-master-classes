1. What is CI/CD?

CI means Continuous Integration: automatically build and test code when changes are pushed or merged.

CD means Continuous Delivery/Deployment: automatically prepare or release validated changes to an environment.

Developer ↓ git push ↓ CI pipeline ├── Install ├── Lint ├── Test └── Build ↓ Deploy ↓ Environment
Interview idea: CI/CD reduces manual steps and catches problems earlier. A good pipeline should be repeatable, observable and safe.

2. Git

Git is a distributed version control system. It tracks changes and lets developers work safely with branches, commits and merges.

Working tree ↓ git add Staging area ↓ git commit Local repository ↓ git push Remote repository

3. Important Git Commands

git clone <repo>

git commit -m "Add login"
git pull
git push

Know what each command does rather than memorizing commands only.

4. Branching

main ├── feature/login ├── feature/dashboard └── fix/header ↓ Pull Request ↓ Review ↓ Merge ↓ main

A team can protect the main branch so changes must pass review and CI before merging.

5. Merge vs Rebase

MergeRebase
Combines histories with a merge commit when needed.Replays commits onto another base.
Preserves branch history.Creates a cleaner linear history.
Does not rewrite existing commits.Rewrites commit history being rebased.
Never casually rebase shared/public history. A practical team rule is to rebase your own local feature work before sharing when appropriate.

6. Pull Request Flow

Feature branch ↓ Push ↓ Pull Request ↓ CI checks ├── lint ├── tests └── build ↓ Code review ↓ Merge

7. GitHub Actions

GitHub Actions is GitHub's automation platform. A workflow is defined in YAML and can run on events such as pushes or pull requests.

name: CI

on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 20

      - run: npm ci
      - run: npm run lint
      - run: npm test
      - run: npm run build

8. Workflow → Job → Step

Workflow ↓ Job ├── Step 1: checkout ├── Step 2: setup Node ├── Step 3: install ├── Step 4: test └── Step 5: build

A workflow can contain multiple jobs, and jobs can run sequentially or in parallel depending on dependencies.

9. GitHub Actions Secrets

Secrets should not be hardcoded into workflow files or source code.

steps:
  - run: npm run deploy
    env:
      DEPLOY_TOKEN: ${{ secrets.DEPLOY_TOKEN }}
Secrets should be stored using the platform's secret-management mechanism. Also avoid printing secret values into logs.

10. CI Pipeline for React

Pull Request ↓ Checkout ↓ Install dependencies ↓ Lint ↓ Unit tests ↓ Build ↓ Optional E2E/security checks ↓ Approve + Merge

The pipeline should fail early when a required quality check fails.

11. Deployment

Deployment means making an application version available in an environment such as development, staging or production.

EnvironmentPurpose
DevelopmentLocal development and rapid experimentation.
StagingPre-production validation.
ProductionReal users and live traffic.

12. Deployment Flow

Code ↓ Git ↓ CI ↓ Build ↓ Artifact ↓ Staging ↓ Validation ↓ Production ↓ Monitoring

13. Build Artifact

A build artifact is the output produced by the build process that can be deployed.

npm run build

dist/
├── index.html
├── assets/
│   ├── index-xxxxx.js
│   └── index-xxxxx.css
└── ...

For a static React app, the dist directory commonly contains the deployable static assets.

14. Docker Basics

Docker packages an application and its dependencies into a container image that can run consistently across environments.

Dockerfile ↓ docker build ↓ Image ↓ docker run ↓ Container

An image is a packaged template; a container is a running instance of an image.

15. Dockerfile Example — React App

# Build stage
FROM node:20-alpine AS build

WORKDIR /app
COPY package*.json ./
RUN npm ci

COPY . .
RUN npm run build

# Runtime stage
FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html

This is a common multi-stage pattern: Node builds the application, while a small web server image serves the generated static files.

16. Image vs Container

ImageContainer
Packaged, immutable template.Running instance of an image.
Built from a Dockerfile or another image.Created/run from an image.
Can be stored in a registry.Has runtime state/processes.

17. Docker Commands

18. Why Multi-Stage Docker Builds?

Large build image Node + npm + source ↓ Build ↓ Only dist/ ↓ Small runtime image Nginx + static files

The final image does not need the complete Node toolchain just to serve static files, reducing image size and attack surface.

19. Vercel

Vercel is a deployment platform commonly used for frontend applications and frameworks such as Next.js.

Git repository ↓ Vercel detects change ↓ Install dependencies ↓ Build ↓ Deploy ↓ CDN / Edge delivery

It can create preview deployments for changes so teams can review a version before production.

20. Netlify

Netlify is a platform for deploying web applications and static sites with build automation, previews and CDN-based delivery.

Git push ↓ Netlify build ↓ Build command ↓ Publish directory ↓ Deployment

For a Vite React app, the typical build output is dist, although the exact configuration depends on the project.

21. Vercel vs Netlify

VercelNetlify
Strong integration with Next.js and modern frontend deployments.Strong static/frontend deployment workflow.
Preview deployments and Git integration.Preview deployments and Git integration.
CDN/edge-oriented platform features.CDN/serverless-oriented platform features.
Excellent choice for many Next.js projects.Excellent choice for many static/Jamstack projects.
The best platform depends on the framework, runtime needs, team workflow, pricing and required platform features.

22. SPA Routing on Static Hosting

React Router client-side routes need the host to return the application's entry HTML for routes that are not physical files.

/dashboard ↓ Server looks for /dashboard ↓ No physical file ↓ SPA fallback → index.html ↓ React Router handles /dashboard

Without the correct rewrite/fallback configuration, refreshing a nested route may return a server 404.

24. Deployment Strategies

RollingGradually replace old instances with new ones.

Static frontend platforms may abstract these details, but the concepts are useful in interviews and production systems.

25. Rollback

A rollback returns production to a previously known-good version.

Version 101 ↓ Production ↓ Bug discovered ↓ Rollback ↓ Version 100 ↓ Stable

Fast rollback is one reason immutable builds and versioned deployments are valuable.

26. CI vs CD vs Deployment

TermMeaning
CIAutomatically integrate and validate code changes.
Continuous DeliveryKeep validated changes ready for release.
Continuous DeploymentAutomatically release validated changes to production.
DeploymentThe act of making a version available in an environment.

27. Good CI/CD Pipeline

  • Fast feedback.
  • Deterministic dependency installation.
  • Linting and tests.
  • Production build verification.
  • Secure secrets.
  • Preview/staging validation.
  • Observability after deployment.
  • Simple rollback path.

28. Common CI/CD Mistakes

  • Deploying without running tests/build.
  • Using npm install when reproducible CI should use npm ci with a lockfile.
  • Hardcoding secrets in YAML or source.
  • Using huge Docker images unnecessarily.
  • Ignoring failed deployments.
  • No rollback strategy.
  • Assuming a successful build means the app is functionally correct.
  • Forgetting SPA rewrite configuration.
  • Putting frontend secrets into environment variables.

Most Asked Interview Questions

  1. What is CI/CD? Automated integration, validation and delivery/deployment of software changes.
  2. What is Git? A distributed version control system for tracking source changes and collaborating through commits and branches.
  3. What is a branch? A separate line of development pointing to a sequence of commits.
  4. Merge vs rebase? Merge combines histories; rebase replays commits onto a new base and rewrites the rebased history.
  5. What is GitHub Actions? GitHub's automation platform for running workflows based on repository events or schedules.
  6. What is a workflow? A YAML-defined automation containing one or more jobs.
  7. What is a job? A group of steps executed on a runner.
  8. Why use npm ci in CI? It installs from the lockfile in a clean, reproducible manner and is designed for automated environments.
  9. What is a deployment artifact? The output of a build that can be released, such as a React dist directory or container image.
  10. What is Docker? A containerization platform used to package and run applications consistently.
  11. Image vs container? Image is the packaged template; container is a running instance.
  12. Why multi-stage Docker builds? To keep build tools out of the final runtime image and reduce size/attack surface.
  13. What is Vercel? A deployment platform commonly used for modern frontend frameworks and web applications.
  14. What is Netlify? A platform for deploying web applications/static sites with build automation and previews.
  15. How does a React SPA handle direct nested routes? The host must usually rewrite unknown application routes to the SPA entry HTML so the client router can handle them.
  16. What is rollback? Returning production to a previously known-good version.
  17. What is continuous delivery vs deployment? Delivery keeps validated changes ready for release; continuous deployment automatically releases them.
  18. How do you secure CI/CD? Protect secrets, use least privilege, pin/lock dependencies where appropriate, review workflows, restrict deployment permissions and avoid exposing credentials in logs.

Scenario-Based Questions

  1. A PR passes locally but CI fails.
    Compare Node/package-manager versions, lockfile state, environment variables and CI-specific commands. Reproduce the CI environment locally where possible.
  2. A developer commits an API secret to Git.
    Revoke/rotate the secret immediately, remove it from active use and clean the repository/history as required by the incident process.
  3. The React build succeeds but production shows a blank page.
    Check browser console/network errors, asset paths, deployment output and environment variables. A successful build does not guarantee correct runtime behavior.
  4. Refreshing /users/123 returns 404.
    Configure the hosting platform's SPA fallback/rewrite to serve index.html for client-side routes.
  5. A Docker image is 1.5 GB for a static React site.
    Use a multi-stage build and a small runtime image such as Nginx rather than shipping Node build dependencies.
  6. Production deployment breaks login.
    Check production environment configuration, API URL, cookie domain/SameSite/Secure settings, CORS and authentication callback URLs.
  7. A GitHub Actions workflow prints a secret.
    Remove the logging, rotate the exposed secret if necessary and audit the workflow for other credential leaks.
  8. A team deploys directly from a developer laptop.
    Move deployment into a repeatable CI/CD process so the same build and checks are used consistently.
  9. A bad release reaches production.
    Rollback to the known-good version, investigate the failure and then fix/retest before redeploying.
  10. Every PR waits 30 minutes for CI.
    Parallelize independent jobs, cache safe dependencies, remove redundant work and keep expensive E2E/security stages appropriately separated.
  11. Two branches modify the same file.
    Git may report a merge conflict. Resolve it carefully, run tests and commit the resolved result.
  12. A developer rebases a shared branch and teammates lose their history.
    Explain that rebase rewrites commit history. Avoid rewriting shared history unless the team explicitly coordinates it.
  13. A frontend environment variable contains a private database password.
    It must not be exposed to the browser. Move the secret operation to a backend/server-side environment.
  14. Vercel preview works but production does not.
    Compare production environment variables, domain configuration, build settings, API/CORS configuration and production-only behavior.
  15. A Netlify deployment succeeds but assets return 404.
    Inspect the publish directory and generated asset paths, then verify the deployment configuration matches the build output.
