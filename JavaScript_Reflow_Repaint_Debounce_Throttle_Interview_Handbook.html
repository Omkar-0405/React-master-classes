1. Reflow vs Repaint

When the page changes, the browser may need to recalculate layout or redraw pixels.

DOM / Style Change ↓ Does geometry change? / \ Yes No ↓ ↓ Reflow Repaint ↓ ↓ Paint Composite \ / Screen

Reflow (Layout)

Reflow happens when the browser must recalculate the size or position of elements.

element.style.width = "500px";
element.style.height = "200px";
element.style.margin = "20px";

These changes can affect the element's geometry and possibly surrounding elements.

Reflow is also commonly called layout.

Repaint

Repaint happens when the browser needs to redraw visual appearance without changing layout geometry.

element.style.color = "red";
element.style.backgroundColor = "black";

Changing colors can require repaint without requiring a new layout.

Reflow vs Repaint

ReflowRepaint
Recalculates layoutRedraws visual appearance
Usually more expensiveUsually cheaper than layout
Width, height, position, geometryColor, background, shadow, etc.

Interview tip: A layout change can lead to paint and compositing work too.

Forced Synchronous Layout

A performance problem can occur when JavaScript writes a style and immediately reads layout information.

box.style.width = "500px";

console.log(box.offsetWidth);

The browser may have to calculate layout immediately to answer offsetWidth.

Repeated read → write → read → write patterns can cause layout thrashing.

How to Reduce Layout Work

  • Batch DOM writes.
  • Read layout values before making writes when possible.
  • Avoid unnecessary DOM changes.
  • Prefer transform/opacity for suitable animations.
  • Use CSS classes instead of many individual style changes when practical.

2. Debounce

Debounce waits until events stop happening for a specified time before running the function.

Events: • • • • • • ↓ wait for gap ↓ Run ✓

Simple idea: "Run after the user stops."

Debounce Implementation

function debounce(fn, delay) {
  let timer;

  return function (...args) {
    clearTimeout(timer);

    timer = setTimeout(() => {
      fn.apply(this, args);
    }, delay);
  };
}

Usage

const search = debounce((value) => {
  console.log("API call:", value);
}, 500);

input.addEventListener("input", e => {
  search(e.target.value);
});

If the user types continuously, the timer keeps resetting. The API call happens after typing stops for 500ms.

Debounce Use Cases

  • Search box API requests.
  • Autocomplete.
  • Form validation after typing stops.
  • Resize handling when only the final size matters.
  • Autosave after the user stops editing.

3. Throttle

Throttle limits a function to running at most once during a specified interval.

Events: • • • • • • • • ↓ Run ✓ ↓ wait 200ms ↓ Run ✓ ↓ wait ↓ Run ✓

Simple idea: "Run at most once every X milliseconds."

Throttle Implementation

function throttle(fn, delay) {
  let lastCall = 0;

  return function (...args) {
    const now = Date.now();

    if (now - lastCall >= delay) {
      lastCall = now;
      fn.apply(this, args);
    }
  };
}

Usage

const handleScroll = throttle(() => {
  console.log("scrolling");
}, 200);

window.addEventListener("scroll", handleScroll);

The function can run at most once per 200ms with this simple implementation.

Throttle Use Cases

  • Scroll events.
  • Mouse movement.
  • Window resize when periodic updates are useful.
  • Drag events.
  • Continuous position tracking.

React Connection

const debouncedSearch = useMemo(
  () => debounce(searchUsers, 500),
  []
);

In React, be careful with function identity, cleanup and stale closures when using debounce/throttle inside components. Libraries or well-tested hooks can simplify this.

Most Asked Interview Questions

  1. What is reflow? Recalculation of element layout and geometry.
  2. What is repaint? Redrawing visual appearance.
  3. Which is usually more expensive? Reflow/layout is generally more expensive because it can affect surrounding geometry.
  4. Can repaint happen without reflow? Yes, for many visual-only changes.
  5. What is layout thrashing? Repeated forced layout caused by alternating DOM writes and layout reads.
  6. What is debounce? Run after events stop for a chosen delay.
  7. What is throttle? Limit execution to at most a controlled frequency.
  8. Debounce vs throttle? Debounce waits for silence; throttle allows periodic execution.
  9. Where would you use debounce? Search, autocomplete and autosave.
  10. Where would you use throttle? Scroll, drag and continuous mouse events.
  11. Why use transform for animation? It can often avoid layout and be handled efficiently during compositing.
  12. Why can debounce/throttle be tricky in React? Function identity, cleanup and closures must be handled correctly.

Scenario-Based Questions

  1. User types in a search box and you want one API request after they stop.
    Use debounce.
  2. You need scroll position updates while scrolling, but not on every event.
    Use throttle.
  3. An element's width changes and surrounding elements move.
    Layout/reflow may occur.
  4. You only change text color.
    This can require repaint without layout.
  5. You change width and immediately read offsetHeight.
    This can force synchronous layout.
  6. A scroll handler makes expensive calculations hundreds of times per second.
    Throttle it.
  7. An autosave should happen after the user stops typing.
    Debounce it.
  8. A drag interaction needs regular updates during movement.
    Throttle is often more appropriate.
  9. An animation changes left repeatedly.
    Consider transform instead, when appropriate, to reduce layout work.
  10. You need to process only the final resize dimensions.
    Debounce resize handling.
  11. You need periodic resize updates while resizing.
    Throttle resize handling.
  12. A React debounce creates a new timer every render.
    Stabilize the debounced function and clean it up appropriately.

Quick Revision

  • ✔ Reflow = layout recalculation.
  • ✔ Repaint = redraw visual appearance.
  • ✔ Layout changes can lead to paint/composite work.
  • ✔ Debounce = run after events stop.
  • ✔ Throttle = run at controlled intervals.
  • ✔ Search/autosave → debounce.
  • ✔ Scroll/drag/mousemove → throttle.
  • ✔ Avoid forced synchronous layout and layout thrashing.
