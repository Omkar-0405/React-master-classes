1. Why React?

React is a JavaScript library for building user interfaces using reusable components.

  • Component-based: break UI into small reusable pieces.
  • Declarative: describe what the UI should look like.
  • Reusable: components can be used in many places.
  • Ecosystem: works with routing, state management, data fetching and many other tools.
function Welcome() {
  return <h1>Hello React</h1>;
}

2. Real DOM

The DOM is the browser's object representation of the HTML document.

document.querySelector("#title").textContent = "Hello";

Direct DOM changes can become difficult to manage when a large UI has many changing parts.

3. Virtual DOM

The Virtual DOM is an in-memory representation of UI that React uses to determine what DOM changes are needed.

State / Props change ↓ React creates new UI description ↓ Compare with previous result ↓ Determine necessary DOM updates ↓ Browser DOM

Important: React does not update the real DOM for every component calculation. It calculates changes and commits the necessary DOM updates.

4. JSX

JSX is a syntax extension that lets you write UI markup inside JavaScript.

const element = <h1>Hello {name}</h1>;

JSX is transformed into JavaScript. It is not HTML itself.

5. Babel

Babel is a JavaScript compiler/transformation tool. In React projects, it can transform JSX and modern JavaScript syntax into code that the configured environment can understand.

const element = <h1>Hello</h1>;

Conceptually, JSX is transformed into JavaScript calls used to describe the React element tree.

6. ReactDOM

react-dom provides React-specific DOM APIs for browser applications.

import { createRoot } from "react-dom/client";
import App from "./App";

createRoot(document.getElementById("root"))
  .render(<App />);

createRoot() creates a React root, and render() starts rendering the application into the DOM.

JSX Rules

  • Return one parent element, or use a Fragment.
  • Close tags properly.
  • Use className instead of HTML class.
  • Use camelCase for most DOM properties/events.
  • JavaScript expressions go inside {}.
function User() {
  const name = "Omkar";

  return (
    <div className="user">
      <h2>{name}</h2>
    </div>
  );
}

JSX Expressions

Use braces to insert JavaScript expressions.

const age = 25;

return <p>Age: {age}</p>;

You can use expressions such as calculations, function calls and ternaries.

<p>{age >= 18 ? "Adult" : "Minor"}</p>

Statements such as if cannot be placed directly inside JSX braces.

Fragments

Fragments let a component return multiple elements without adding an extra DOM element.

return (
  <>
    <h1>Title</h1>
    <p>Description</p>
  </>
);

Long form: <React.Fragment>...</React.Fragment>.

Conditional Rendering

function User({ isLoggedIn }) {
  return (
    <div>
      {isLoggedIn ? <Dashboard /> : <Login />}
    </div>
  );
}

Common approaches: ternary, &&, early return and variables.

Tip: Be careful with 0 && <Component />; it renders 0.

Lists

const users = [
  { id: 1, name: "A" },
  { id: 2, name: "B" }
];

return (
  <ul>
    {users.map(user => (
      <li key={user.id}>{user.name}</li>
    ))}
  </ul>
);

When rendering a collection, each sibling needs a stable key.

Functional Components

A function component is a JavaScript function that returns React elements.

function Button({ text }) {
  return <button>{text}</button>;
}

Modern React primarily uses function components with Hooks.

Class Components

Class components extend React.Component. They are still supported, but new React code generally uses function components.

class Welcome extends React.Component {
  render() {
    return <h1>Hello {this.props.name}</h1>;
  }
}

Smart vs Presentational Components

TypeTypical Responsibility
Smart / ContainerCoordinates state, data fetching and business logic.
PresentationalFocuses mainly on displaying UI based on props.

This is a design pattern, not a special React component type.

Higher Order Components (HOC)

A HOC is a function that takes a component and returns an enhanced component.

function withLoading(Component) {
  return function Enhanced(props) {
    if (props.loading) return <p>Loading...</p>;
    return <Component {...props} />;
  };
}

HOCs were common before Hooks. They are still useful in some libraries and legacy code.

Compound Components

Compound components work together through a shared parent API.

<Tabs>
  <Tabs.List>
    <Tabs.Tab>Profile</Tabs.Tab>
    <Tabs.Tab>Settings</Tabs.Tab>
  </Tabs.List>

  <Tabs.Panel>Content</Tabs.Panel>
</Tabs>

This pattern is useful for flexible, readable component APIs.

Props

Props are read-only inputs passed from a parent component to a child.

function User({ name, age }) {
  return <p>{name} - {age}</p>;
}

<User name="Omkar" age={25} />

The child should not mutate its props.

Children

children contains content placed between a component's opening and closing tags.

function Card({ children }) {
  return <div className="card">{children}</div>;
}

<Card>
  <h2>Profile</h2>
  <p>Details</p>
</Card>

Default Props

For function components, a common modern approach is a default parameter value.

function Button({ text = "Submit" }) {
  return <button>{text}</button>;
}

If the prop is undefined, the default is used. null does not trigger the default parameter.

Prop Drilling

Prop drilling means passing data through intermediate components that do not actually need the data, only so a deeper component can receive it.

App ↓ props Layout ↓ props Sidebar ↓ props UserProfile

Possible solutions include component composition, Context or a state-management library, depending on the problem.

State

State is data owned by a component or application that can change over time and cause the UI to update.

import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(c => c + 1)}>
      {count}
    </button>
  );
}

Local State

State used by one component or a small component subtree.

const [isOpen, setIsOpen] = useState(false);

Shared State

State used by multiple components. Often, the state is moved to their closest common parent and passed down through props.

Parent owns state ↓ ↓ Child A Child B

For larger applications, Context or a state-management library may be appropriate.

Derived State

Derived state is a value that can be calculated from existing props/state.

const fullName = `${firstName} ${lastName}`;

Do not store a value separately in state when it can be reliably calculated from existing data. This avoids synchronization bugs.

Initial Render

The first time React renders the component tree, it creates the initial UI and commits the necessary DOM updates.

App starts ↓ Render component tree ↓ Commit DOM changes ↓ Browser displays UI

Re-render

A re-render means React calls a component again to calculate its next UI result. It can happen because of state changes, parent renders or changed context/props.

Important: A component re-render does not automatically mean the browser DOM is completely rebuilt.

Reconciliation

Reconciliation is React's process of comparing the previous and next element trees to determine what needs to change.

Previous UI ↓ Compare ↑ Next UI ↓ Necessary changes ↓ Commit DOM updates

Keys

Keys give React a stable identity for elements in a list.

{users.map(user => (
  <User key={user.id} user={user} />
))}

Keys help React match old and new children during reconciliation.

Stable Keys

A good key is:

  • Unique among the siblings.
  • Stable across renders.
  • Based on the item's identity.

Database IDs are often good keys.

Why Index Keys Can Cause Problems

// Avoid when list order can change
items.map((item, index) => (
  <Item key={index} item={item} />
));

If items are inserted, removed or reordered, the same index may refer to a different item. React can then preserve component state against the wrong item.

Index keys are generally okay for truly static lists where items never reorder, insert, or delete.

Complete React Mental Model

Props / State change ↓ Component renders ↓ New React element tree ↓ Reconciliation ↓ Commit necessary DOM changes ↓ Browser rendering ↓ Screen

Most Asked Interview Questions

  1. Why React? It provides a component-based, declarative way to build dynamic UIs.
  2. Virtual DOM vs Real DOM? Virtual DOM is React's in-memory UI representation; Real DOM is the browser's actual document tree.
  3. What is JSX? A syntax extension for describing UI inside JavaScript.
  4. What does Babel do? It transforms JSX and modern JavaScript according to the project's configuration.
  5. What is ReactDOM? The package that provides browser DOM integration APIs such as createRoot.
  6. What are props? Read-only inputs passed from parent to child.
  7. What is prop drilling? Passing props through components that do not need them to reach a deeper component.
  8. Local vs shared state? Local state belongs to one component/subtree; shared state is needed by multiple components.
  9. What is derived state? A value calculated from existing props/state rather than independently stored.
  10. What causes a re-render? Common causes include state updates, parent renders, changed props and relevant context updates.
  11. What is reconciliation? Comparing previous and next React element trees to determine necessary updates.
  12. Why are keys required? They provide stable identity for list items during reconciliation.
  13. Why is index a bad key? When a list changes order/length, indexes can point to different items and cause incorrect state association.
  14. What is an HOC? A function that takes a component and returns an enhanced component.
  15. What are compound components? A group of components designed to work together through a shared parent API.

Scenario-Based Questions

  1. You need a reusable button used across many pages.
    Create a function component and pass differences through props.
  2. A child needs to display a parent's data.
    Pass the data through props.
  3. A deep child needs data and many intermediate components do not use it.
    Consider composition, Context or suitable shared state instead of excessive prop drilling.
  4. Two sibling components need the same changing state.
    Lift the state to their closest common parent and pass the needed data/callbacks.
  5. A value can be calculated from existing state.
    Prefer derived data instead of storing duplicate state.
  6. A list of users is rendered from API data.
    Use map and a stable unique key such as the user ID.
  7. A list can be reordered by drag-and-drop.
    Do not use the array index as the key; use a stable item ID.
  8. A list item contains an input and items are inserted at the beginning.
    Use stable IDs so input state stays associated with the correct item.
  9. A component's state changes.
    React re-renders the relevant component tree and reconciles the result before committing necessary DOM changes.
  10. A parent re-renders.
    Its children may also be evaluated again; React then determines whether DOM changes are actually needed.
  11. You need multiple sibling JSX elements without an extra div.
    Use a Fragment.
  12. You need to show either Login or Dashboard.
    Use conditional rendering such as a ternary or early return.
  13. You have a reusable component that wraps arbitrary content.
    Use the children prop.
  14. You want to add loading behavior around many components.
    A HOC can be used, although modern React often favors Hooks and composition.
  15. You want a flexible Tabs API.
    Compound components can provide a clean API such as Tabs.List, Tabs.Tab and Tabs.Panel.
