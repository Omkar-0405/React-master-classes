Section 5 — React Hooks

Simple Interview Handbook • Most Important React Interview Topics

Hooks — Big Picture

Hooks let function components use state, effects, refs, context, memoization and other React features.

Component │ ├── useState → state ├── useEffect → external synchronization ├── useMemo → cached calculation ├── useCallback → cached function ├── useRef → persistent mutable reference ├── useContext → consume context └── useReducer → reducer-based state
Core rule: Hooks must be called at the top level of a function component or custom Hook, not inside loops, conditions or nested functions.

1. useState — Basics

useState adds local state to a function component.

const [count, setCount] = useState(0);

return (
  <button onClick={() => setCount(count + 1)}>
    {count}
  </button>
);

The setter schedules a state update. The component renders again with the new state.

useState — Objects and Arrays

Do not mutate state directly. Create a new object or array.

const [user, setUser] = useState({
  name: "Omkar",
  age: 25
});

setUser(prev => ({
  ...prev,
  age: 26
}));
const [items, setItems] = useState([]);

setItems(prev => [...prev, newItem]);

useState — Updater Function

When the next state depends on the previous state, use the updater form.

setCount(c => c + 1);
setCount(c => c + 1);
setCount(c => c + 1);

This correctly applies three updates based on the latest queued state.

Prefer this form whenever the new value depends on the old value.

useState — Batching

React can batch multiple state updates so they are processed together, reducing unnecessary renders.

function handleClick() {
  setCount(c => c + 1);
  setName("Omkar");
  setOpen(true);
}

In modern React, automatic batching also applies in many asynchronous contexts, not only React event handlers.

Interview point: Do not assume every setter immediately changes the current variable. The current render's state value remains fixed for that render.

useState — Lazy Initialization

If initial state requires an expensive calculation, pass a function so React can initialize it lazily.

const [data, setData] = useState(() => {
  return expensiveCalculation();
});

Use useState(createInitialState), not useState(createInitialState()), when you want the initializer function form.

useEffect — Purpose

useEffect is used to synchronize a component with an external system: network requests, subscriptions, timers, browser APIs, third-party widgets, etc.

useEffect(() => {
  const connection = connect();

  return () => {
    connection.disconnect();
  };
}, []);
Render ↓ DOM commit ↓ Effect setup ↓ Dependency changes ↓ Cleanup old effect ↓ Setup new effect

Keep rendering itself pure; effects happen outside the render calculation.

useEffect — Dependency Array

CodeMeaning
useEffect(fn)Runs after every committed render.
useEffect(fn, [])Setup after mount; cleanup on unmount. Development Strict Mode can perform an extra setup/cleanup cycle.
useEffect(fn, [id])Runs after mount and when id changes.

Dependencies should include reactive values used by the effect, according to the effect's logic and the project's linting rules.

useEffect — Cleanup

Cleanup prevents subscriptions, timers and listeners from remaining active.

useEffect(() => {
  const onResize = () => console.log(window.innerWidth);

  window.addEventListener("resize", onResize);

  return () => {
    window.removeEventListener("resize", onResize);
  };
}, []);

Cleanup also runs before an effect re-runs because its dependencies changed.

useEffect — Infinite Loops

An effect can loop when it updates a value that causes the effect to run again.

// Problem
const [count, setCount] = useState(0);

useEffect(() => {
  setCount(count + 1);
}, [count]);

Each effect updates count, which triggers another effect. Avoid effects that derive state unnecessarily.

useEffect — Stale Closure

An effect or callback can capture an older value from the render in which it was created.

useEffect(() => {
  const id = setInterval(() => {
    console.log(count);
  }, 1000);

  return () => clearInterval(id);
}, []);

This interval keeps the value captured by the initial effect. Solutions depend on the goal: correct dependencies, functional state updates, or a ref for mutable latest values.

useEffect — Fetch

useEffect(() => {
  let ignore = false;

  async function load() {
    const response = await fetch("/api/user");
    const data = await response.json();

    if (!ignore) {
      setUser(data);
    }
  }

  load();

  return () => {
    ignore = true;
  };
}, [userId]);

The cleanup prevents an older response from updating state after the component no longer wants that result.

useEffect — AbortController

For fetch requests, AbortController can cancel an in-flight request.

useEffect(() => {
  const controller = new AbortController();

  fetch(`/api/users/${userId}`, {
    signal: controller.signal
  })
    .then(res => res.json())
    .then(data => setUser(data))
    .catch(error => {
      if (error.name !== "AbortError") {
        console.error(error);
      }
    });

  return () => controller.abort();
}, [userId]);

This is useful when a request becomes irrelevant because the dependency changed or the component unmounted.

useEffect — Race Conditions

Suppose the user requests A, then quickly requests B. B may finish first, but A could finish later and overwrite B.

Request A ───────────────► response A Request B ─────► response B If A finishes last: old A could overwrite newer B ❌

Use cancellation with AbortController or an ignore/staleness strategy so only the relevant request updates state.

useEffect — Multiple Effects

Use separate effects for unrelated synchronization concerns.

useEffect(() => {
  document.title = title;
}, [title]);

useEffect(() => {
  const id = setInterval(sync, 5000);
  return () => clearInterval(id);
}, []);

Multiple focused effects are often clearer than one large effect containing unrelated work.

2. useLayoutEffect

useLayoutEffect runs after DOM mutations but before the browser paints. It is useful when you must measure or synchronously adjust layout before the user sees the result.

useLayoutEffect(() => {
  const rect = ref.current.getBoundingClientRect();
  setWidth(rect.width);
}, []);
useEffectuseLayoutEffect
Normal effect/synchronizationLayout-sensitive work
Does not block paint in the normal caseRuns before paint and can block it
Preferred by defaultUse only when timing requires it

3. useMemo

useMemo caches the result of a calculation between renders until its dependencies change.

const filteredUsers = useMemo(() => {
  return users.filter(user =>
    user.name.includes(search)
  );
}, [users, search]);

It is useful when a calculation is genuinely expensive or when a stable value is important for another optimization.

Do not use useMemo everywhere. Memoization has its own cost and makes code more complex. Measure or reason about the optimization first.

4. useCallback

useCallback caches a function reference until dependencies change.

const handleSelect = useCallback((id) => {
  setSelectedId(id);
}, []);

This is mainly useful when passing a callback to a memoized child or when a stable function identity matters.

useMemo + React.memo + useCallback

const Child = React.memo(function Child({ onClick }) {
  return <button onClick={onClick}>Click</button>;
});

function Parent() {
  const handleClick = useCallback(() => {
    console.log("clicked");
  }, []);

  return <Child onClick={handleClick} />;
}
Parent renders ↓ useCallback keeps same function reference ↓ React.memo child receives same props ↓ Child may skip its render

All three tools are optimizations, not requirements.

5. useRef

useRef returns a persistent object whose current value can change without causing a re-render.

const inputRef = useRef(null);

function focusInput() {
  inputRef.current.focus();
}

return (
  <>
    <input ref={inputRef} />
    <button onClick={focusInput}>Focus</button>
  </>
);

useRef — Mutable Variable

const timerRef = useRef(null);

timerRef.current = setTimeout(() => {
  console.log("done");
}, 1000);

Changing ref.current does not cause a re-render.

useRef — Previous State

const previousCount = useRef();

useEffect(() => {
  previousCount.current = count;
}, [count]);

console.log(previousCount.current);

A ref can hold a value from the previous render, depending on when it is updated.

6. useContext

Context lets components read shared values without passing props through every intermediate component.

const ThemeContext = createContext("light");

function App() {
  return (
    <ThemeContext.Provider value="dark">
      <Page />
    </ThemeContext.Provider>
  );
}

function Button() {
  const theme = useContext(ThemeContext);
  return <button>{theme}</button>;
}

Context is useful for values such as theme, locale and application-level configuration.

Context Performance

When a context value changes, components consuming that context can re-render.

const value = useMemo(() => ({
  user,
  logout
}), [user, logout]);

Splitting contexts, stabilizing provider values where useful, and keeping providers appropriately scoped can reduce unnecessary work. Do not memoize blindly.

7. useReducer

useReducer manages state through a reducer function and dispatched actions.

function reducer(state, action) {
  switch (action.type) {
    case "increment":
      return { count: state.count + 1 };
    case "reset":
      return { count: 0 };
    default:
      return state;
  }
}

const [state, dispatch] = useReducer(reducer, {
  count: 0
});

dispatch({ type: "increment" });
User action ↓ dispatch(action) ↓ reducer(state, action) ↓ new state ↓ render

When useReducer?

It is useful when state has multiple related fields, many transitions, or complex update rules.

For a simple boolean or counter, useState is usually easier.

8. Custom Hooks

A custom Hook is a function whose name starts with use and that can call other Hooks.

function useWindowWidth() {
  const [width, setWidth] = useState(window.innerWidth);

  useEffect(() => {
    const update = () => setWidth(window.innerWidth);
    window.addEventListener("resize", update);

    return () => {
      window.removeEventListener("resize", update);
    };
  }, []);

  return width;
}

Custom Hooks share logic, not state itself. Each component calling the Hook gets its own Hook state.

Custom Hook Rules

  • Name should start with use.
  • Follow the Rules of Hooks.
  • Call Hooks only at the top level.
  • Call custom Hooks from function components or other Hooks.
  • Extract reusable behavior, not arbitrary UI.

9. useImperativeHandle

Lets a component customize what a parent receives through a ref.

function Input({ ref }) {
  useImperativeHandle(ref, () => ({
    focus() {
      inputRef.current.focus();
    }
  }));

  const inputRef = useRef(null);

  return <input ref={inputRef} />;
}

Use it sparingly. Declarative props are usually preferred. It is useful when a parent genuinely needs an imperative action such as focus or scroll.

10. forwardRef

Traditionally, forwardRef lets a ref pass through a function component to a DOM node or child.

const Input = forwardRef(function Input(props, ref) {
  return <input ref={ref} {...props} />;
});

Modern React note: In React 19, function components can receive ref as a prop, so new code may not need forwardRef. You will still encounter forwardRef in existing code and libraries.

11. useDeferredValue

useDeferredValue lets a non-urgent part of the UI lag behind an urgent value so interactions can stay responsive.

const deferredQuery = useDeferredValue(query);

const results = useMemo(
  () => filterLargeList(items, deferredQuery),
  [items, deferredQuery]
);

It does not debounce the value and does not delay the source update itself. It marks the derived UI as less urgent.

12. useTransition

useTransition lets you mark state updates as non-urgent transitions.

const [isPending, startTransition] = useTransition();

function selectTab(tab) {
  startTransition(() => {
    setTab(tab);
  });
}

isPending can be used to show feedback while the transition is being processed.

useTransition vs useDeferredValue

useTransitionuseDeferredValue
Marks a state update as non-urgent.Creates a deferred version of a value.
You control the update with startTransition.You defer a value already produced by another update.

13. useId

useId generates stable unique IDs useful for associating labels and form controls, especially when components can render in different environments.

function EmailField() {
  const id = useId();

  return (
    <>
      <label htmlFor={id}>Email</label>
      <input id={id} />
    </>
  );
}

Do not use useId for list keys or general data IDs.

14. useSyncExternalStore

useSyncExternalStore is for subscribing to an external store in a way that integrates correctly with React's rendering model.

const value = useSyncExternalStore(
  store.subscribe,
  store.getSnapshot
);

It is mainly useful for library authors or custom external-store integrations rather than ordinary component state.

15. useInsertionEffect

useInsertionEffect is mainly intended for CSS-in-JS library authors who need to insert styles before layout effects run.

useInsertionEffect(() => {
  // Insert styles here in a CSS-in-JS library.
}, []);

Application code should almost never need it. Prefer normal CSS or other appropriate styling approaches.

Most Asked Interview Questions

  1. What is useState? A Hook for local component state.
  2. Why use the updater function? When the next state depends on the previous state.
  3. What is batching? React groups multiple state updates to reduce unnecessary rendering work.
  4. What is lazy initialization? Passing an initializer function so initial state calculation is performed lazily.
  5. What is useEffect? A Hook for synchronizing a component with external systems.
  6. What does the dependency array do? It controls when an effect's setup is re-run based on its reactive dependencies.
  7. What is effect cleanup? A function returned from the effect that removes/undoes external subscriptions or resources.
  8. What is a stale closure? Code captures values from an older render and later uses those old values.
  9. How do you prevent fetch race conditions? Cancel obsolete requests with AbortController or ignore stale results.
  10. useEffect vs useLayoutEffect? useLayoutEffect runs before paint; useEffect is the normal choice for effects.
  11. useMemo vs useCallback? useMemo caches a value; useCallback caches a function reference.
  12. Does useRef cause re-render? No, changing ref.current does not trigger a render.
  13. When useReducer? When state transitions are complex or strongly related.
  14. What is a custom Hook? Reusable stateful logic packaged in a function that follows Hook rules.
  15. useTransition vs useDeferredValue? Transition marks an update as non-urgent; deferred value creates a lower-priority version of a value.
  16. What is useId for? Stable unique IDs for accessibility and related UI associations, not list keys.
  17. What is useSyncExternalStore? A Hook for subscribing to external stores in a React-compatible way.
  18. Who normally uses useInsertionEffect? Primarily CSS-in-JS library authors.

Scenario-Based Questions

  1. A counter increments based on its current value.
    Use setCount(c => c + 1).
  2. Three state updates depend on previous state.
    Use updater functions so React can apply them sequentially to the queued state.
  3. Initial state requires an expensive calculation.
    Use lazy initialization: useState(() => expensive()).
  4. A component subscribes to a WebSocket.
    Use an Effect and return cleanup that unsubscribes/closes it.
  5. A fetch for user A finishes after user B's fetch.
    Cancel or ignore the obsolete A request so it cannot overwrite B.
  6. A fetch should be cancelled when userId changes.
    Use AbortController in the Effect cleanup.
  7. An effect keeps running forever.
    Check whether it updates a dependency that causes itself to run again, and whether the effect is needed at all.
  8. An interval always logs an old state value.
    Check for a stale closure; use correct dependencies, functional updates, or a ref depending on the requirement.
  9. You need two unrelated subscriptions.
    Use separate focused Effects when that makes dependencies and cleanup clearer.
  10. A calculation filters 100,000 items and is genuinely expensive.
    Consider useMemo if profiling/reasoning shows the calculation is a bottleneck.
  11. A memoized child keeps re-rendering because a callback prop changes every parent render.
    Consider useCallback together with React.memo when the optimization is justified.
  12. You need to focus an input after clicking a button.
    Use useRef to hold the DOM node.
  13. You need a mutable timer ID without causing renders.
    Store it in a ref.
  14. Several components need the current theme.
    Use Context when prop drilling would be unnecessary.
  15. A form has many related state transitions.
    Consider useReducer for explicit actions and centralized transition logic.
  16. Two components need the same reusable subscription logic.
    Create a custom Hook.
  17. A parent needs an imperative focus method from a child.
    Use a ref with useImperativeHandle when a declarative prop is not suitable.
  18. A large list makes typing feel slow.
    Consider useDeferredValue or useTransition to keep urgent interactions responsive.
  19. You need to mark a tab switch as non-urgent.
    Wrap the state update in startTransition.
  20. You need a label/input ID that is unique across component instances.
    Use useId.
  21. You are integrating an external state store.
    Consider useSyncExternalStore for a React-compatible subscription.
  22. You are writing a CSS-in-JS library.
    useInsertionEffect may be relevant; ordinary app code generally should not use it.
