Section 4 — React Lifecycle

Simple Interview Handbook • Functional Lifecycle • Class Lifecycle • Error Boundaries

1. What is the React Lifecycle?

The lifecycle describes what happens to a component from the time it appears, through updates, until it is removed.

MOUNT Component appears ↓ RENDER ↓ COMMIT ↓ Component visible UPDATE Props / State / Context change ↓ RENDER ↓ COMMIT ↓ Updated UI UNMOUNT Component removed ↓ Cleanup

Modern React function components use Hooks such as useEffect for synchronization and cleanup rather than class lifecycle methods.

2. Functional Lifecycle — Mount

Mount means a component is being added to the UI for the first time.

function User() {
  useEffect(() => {
    console.log("Mounted");
  }, []);

  return <h1>User</h1>;
}

With an empty dependency array, the effect setup runs after the component commits on mount. In development Strict Mode, React may run an extra setup/cleanup cycle to help detect unsafe effects.

3. Functional Lifecycle — Update

A function component may render again when its state changes, its parent renders, its props change, or relevant context changes.

function Counter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    console.log("Count changed:", count);
  }, [count]);

  return (
    <button onClick={() => setCount(c => c + 1)}>
      {count}
    </button>
  );
}

The effect runs after a committed render when count has changed.

4. Functional Lifecycle — Unmount

Unmount means the component is removed from the UI.

useEffect(() => {
  const id = setInterval(() => {
    console.log("tick");
  }, 1000);

  return () => {
    clearInterval(id);
  };
}, []);

The returned function is the cleanup. React runs it when the effect is removed, including on unmount.

5. useEffect Lifecycle Pattern

Render ↓ DOM commit ↓ Effect setup ↓ Dependencies change ↓ Previous cleanup ↓ New effect setup ↓ Unmount ↓ Final cleanup

Think of an Effect as synchronizing the component with an external system such as a timer, subscription, event listener or network connection.

7. constructor()

Runs when a class component instance is created.

class Counter extends React.Component {
  constructor(props) {
    super(props);

    this.state = {
      count: 0
    };
  }

  render() {
    return <p>{this.state.count}</p>;
  }
}

Use it mainly for initializing state and binding methods when needed. Modern function components normally use useState.

8. render()

render() returns the UI representation.

render() {
  return <h1>Hello {this.props.name}</h1>;
}

It should be kept free of side effects. Do not perform subscriptions, timers or manual DOM side effects inside render.

9. componentDidMount()

Runs after the component has been mounted and its initial DOM has been committed.

componentDidMount() {
  this.loadUser();
}

Typical uses: subscriptions, DOM work, starting timers and initial client-side data loading.

10. shouldComponentUpdate()

Lets a class component decide whether it should continue with an update.

shouldComponentUpdate(nextProps, nextState) {
  return nextState.count !== this.state.count;
}

Returning false skips the component's update render for that update. Use it carefully; incorrect comparisons can cause stale UI.

Function components commonly use React.memo for similar memoization of props, when appropriate.

11. componentDidUpdate()

Runs after an update has committed.

componentDidUpdate(prevProps) {
  if (prevProps.userId !== this.props.userId) {
    this.loadUser();
  }
}

Always guard operations that could trigger another update to avoid infinite loops.

12. componentWillUnmount()

Runs immediately before the component is removed.

componentWillUnmount() {
  this.subscription.unsubscribe();
  clearInterval(this.timer);
}

Use it to clean up subscriptions, timers and external resources.

13. getSnapshotBeforeUpdate()

Runs after render but immediately before React commits DOM changes. It can capture information from the current DOM that would otherwise be lost after the update.

getSnapshotBeforeUpdate(prevProps, prevState) {
  return this.listRef.current.scrollHeight;
}

componentDidUpdate(prevProps, prevState, snapshot) {
  console.log(snapshot);
}

A classic use case is preserving scroll position in a growing list.

14. Error Boundary

An Error Boundary catches errors thrown during rendering and certain lifecycle methods in its descendant tree and shows fallback UI.

class ErrorBoundary extends React.Component {
  state = { hasError: false };

  static getDerivedStateFromError(error) {
    return { hasError: true };
  }

  componentDidCatch(error, info) {
    console.error(error, info);
  }

  render() {
    if (this.state.hasError) {
      return <h2>Something went wrong.</h2>;
    }

    return this.props.children;
  }
}

Error boundaries are class-based in React's built-in API. They do not catch every kind of error, such as ordinary event-handler errors or server-side errors.

useEffect vs useLayoutEffect

useEffect is the normal choice for side effects and external synchronization.

useLayoutEffect runs after DOM mutations but before the browser paints, making it useful for layout measurements that must happen before the user sees the result.

useLayoutEffect(() => {
  const height = ref.current.getBoundingClientRect().height;
}, []);

Prefer useEffect unless you specifically need layout timing.

Important Lifecycle Mental Model

FUNCTION COMPONENT Mount: Render → Commit → Effect Update: Render → Commit → Effect cleanup → Effect setup Unmount: Cleanup CLASS COMPONENT Mount: constructor → render → componentDidMount Update: render → getSnapshotBeforeUpdate → DOM commit → componentDidUpdate Unmount: componentWillUnmount

Most Asked Interview Questions

  1. What are the three major lifecycle phases? Mount, update and unmount.
  2. What is mounting? Adding a component to the UI for the first time.
  3. What is updating? Rendering and committing changes after props, state or context change.
  4. What is unmounting? Removing a component from the UI.
  5. What replaces componentDidMount in function components? Often an effect with an empty dependency array, when the goal is synchronization after mount.
  6. What replaces componentWillUnmount? The cleanup function returned from an Effect.
  7. What is componentDidUpdate used for? Running logic after an update has committed, often guarded by comparing previous and current values.
  8. What is shouldComponentUpdate? A class lifecycle method that can skip an update when appropriate.
  9. What is getSnapshotBeforeUpdate? A method for reading DOM information immediately before the DOM is committed.
  10. What is an Error Boundary? A component that catches certain descendant rendering/lifecycle errors and shows fallback UI.
  11. Why should side effects not run in render? Rendering should stay pure and may be invoked more than once.
  12. useEffect vs useLayoutEffect? useEffect is the normal effect; useLayoutEffect is for work that must happen after DOM mutation but before paint.
  13. Can Error Boundaries catch event-handler errors? No; handle those errors in the event handler itself.
  14. Why is cleanup important? It prevents stale subscriptions, timers, listeners and other external resources from remaining active.

Scenario-Based Questions

  1. You start a WebSocket subscription when a component appears.
    Start it in an Effect and return cleanup that closes/unsubscribes it.
  2. A timer continues after navigating away.
    Clear it in Effect cleanup or componentWillUnmount for a class component.
  3. An API request depends on userId.
    Use an Effect with userId in its dependency list and handle cleanup/race conditions appropriately.
  4. A class component needs initial data loading.
    componentDidMount is the traditional lifecycle method.
  5. A class component needs to react only when userId changes.
    Compare previous props inside componentDidUpdate.
  6. A component needs to read its DOM size before paint.
    Consider useLayoutEffect when necessary.
  7. You need to preserve scroll position before a DOM update in a class component.
    Use getSnapshotBeforeUpdate and consume its value in componentDidUpdate.
  8. A child component throws during rendering.
    Place it under an Error Boundary to show fallback UI.
  9. An error occurs inside an onClick handler.
    Error Boundaries do not catch it; handle the error in the event handler.
  10. An Effect appears to run twice in development.
    Check Strict Mode. Development Strict Mode can perform an extra setup/cleanup cycle to expose unsafe Effects.
  11. You want to prevent unnecessary class-component updates.
    Use shouldComponentUpdate carefully or consider React.PureComponent/React.memo patterns where appropriate.
  12. An Effect sets up an event listener.
    Remove the same listener in cleanup so it does not accumulate across updates.
  13. You put an API call directly in render.
    Move synchronization/side effects out of render, typically into an Effect or another appropriate data-fetching mechanism.
  14. A component is removed because a condition becomes false.
    The component unmounts and its Effect cleanup runs.
  15. A dependency changes for an Effect.
    React cleans up the previous Effect and then runs the new setup after the committed update.
