JavaScript Event Propagation

Simple Interview Handbook • Bubbling • Capturing • Delegation

What is Event Propagation?

When an event happens on an element, the browser moves the event through the DOM tree.

Capturing ↓ Window ↓ Document ↓ Parent ↓ Child ← event target ↑ Bubbling

The three important ideas are capturing, target, and bubbling.

1. Bubbling

In bubbling, the event moves from the target up toward its ancestors.

const parent = document.querySelector("#parent");
const child = document.querySelector("#child");

parent.addEventListener("click", () => {
  console.log("parent");
});

child.addEventListener("click", () => {
  console.log("child");
});

Clicking the child normally produces:

child
parent
Child event ↑ Parent ↑ Document ↑ Window

2. Capturing

Capturing is the opposite direction: the event travels from the outer ancestor toward the target.

parent.addEventListener("click", () => {
  console.log("parent");
}, true);

child.addEventListener("click", () => {
  console.log("child");
}, true);

The third argument true enables capture for this listener.

parent
child
Window ↓ Document ↓ Parent ↓ Child ← target

3. Target Phase

The event eventually reaches the element where the event actually occurred: the target.

Capture → Target → Bubble

For most interview questions, remember the complete order as:

Capturing → Target → Bubbling

4. event.stopPropagation()

Stops the event from continuing to other ancestors or descendants in the propagation path.

child.addEventListener("click", (event) => {
  event.stopPropagation();
});

It does not stop other listeners on the same element. For that, stopImmediatePropagation() is relevant.

5. Event Delegation

Event delegation means putting one event listener on a parent instead of adding separate listeners to many children.

const list = document.querySelector("#list");

list.addEventListener("click", (event) => {
  if (event.target.matches("button")) {
    console.log("Button clicked:", event.target.textContent);
  }
});
Many buttons │ ├── button ├── button ├── button └── button │ ▼ One listener on parent

Delegation works well because events usually bubble.

Why Use Event Delegation?

  • Fewer event listeners.
  • Useful for dynamic elements.
  • Less repetitive code.
  • Can reduce listener management overhead.

It is especially useful for large lists, tables and menus.

event.target vs event.currentTarget

parent.addEventListener("click", (event) => {
  console.log(event.target);
  console.log(event.currentTarget);
});
PropertyMeaning
event.targetThe element where the event originated.
event.currentTargetThe element whose listener is currently running.

These are very important for event delegation.

React Connection

React uses a synthetic event system and handles events through its event infrastructure. The DOM concepts of bubbling, capturing and delegation are still important when working with React events.

function List() {
  const handleClick = (event) => {
    if (event.target.dataset.id) {
      console.log(event.target.dataset.id);
    }
  };

  return (
    <div onClick={handleClick}>
      <button data-id="1">One</button>
      <button data-id="2">Two</button>
    </div>
  );
}

Most Asked Interview Questions

  1. What is event propagation? The movement of an event through the DOM.
  2. What is bubbling? Event travels from target toward ancestors.
  3. What is capturing? Event travels from ancestors toward target.
  4. What is the event flow? Capturing → target → bubbling.
  5. How do you enable capturing? Use a capture listener, such as addEventListener(type, handler, true).
  6. What is event delegation? Handling child events using a listener on a common ancestor.
  7. Why does delegation work? Because events commonly bubble to ancestors.
  8. target vs currentTarget? target is the original event source; currentTarget is the element whose listener is running.
  9. What does stopPropagation do? Stops propagation to other elements in the event path.
  10. stopPropagation vs preventDefault? stopPropagation affects propagation; preventDefault cancels the browser's default action.
  11. Why use delegation for dynamic lists? One parent listener can handle current and newly added children.
  12. Does stopPropagation stop same-element listeners? No; use stopImmediatePropagation when needed.

Scenario-Based Questions

  1. A button click should also trigger a parent click handler.
    Allow bubbling normally.
  2. A child click must not reach the parent handler.
    Use event.stopPropagation() when appropriate.
  3. You have 1,000 list items.
    Use event delegation on the list container.
  4. New list items are added dynamically.
    Delegation avoids attaching a new listener to every new item.
  5. You need to know which button in a list was clicked.
    Use event.target or find the relevant ancestor with closest().
  6. A parent listener needs to know the element it is attached to.
    Use event.currentTarget.
  7. You need an ancestor to handle an event before the target.
    Use capturing.
  8. You want to cancel a link's navigation.
    Use event.preventDefault(), not stopPropagation.
  9. You need to stop the event from reaching ancestors.
    Use stopPropagation().
  10. Two listeners on the same element should not both run.
    Consider stopImmediatePropagation().
  11. A click is on a nested icon inside a button.
    Use closest("button") when delegation needs the button rather than the exact icon target.
  12. A React parent has onClick and a child has onClick.
    Both can run through bubbling unless propagation is stopped.

Quick Revision

  • ✔ Capturing = outside → target.
  • ✔ Target = event's original element.
  • ✔ Bubbling = target → outside.
  • ✔ Delegation = parent handles child events.
  • ✔ event.target = original source.
  • ✔ event.currentTarget = current listener element.
  • ✔ stopPropagation = stop event path propagation.
  • ✔ preventDefault = stop browser default action.
