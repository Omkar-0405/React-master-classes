Simple Interview Handbook • Fetch • Axios • AbortController • Authentication • Errors • Retry • Pagination • Infinite Scroll

1. What is API Integration?

API integration means connecting the React application to a backend/service to send requests and receive data.

React UI ↓ API Client ↓ HTTP Request ↓ Backend / API ↓ Response ↓ Parse + handle ↓ State / Cache ↓ UI
Interview idea: A good API layer handles loading, success, errors, cancellation, authentication, retries and data transformation without scattering duplicated logic across components.

2. Fetch

fetch() is the browser's built-in API for making HTTP requests.

async function getUsers() {
  const response = await fetch("/api/users");

  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }

  return response.json();
}

Important: Fetch does not reject its Promise just because the server returns HTTP 4xx/5xx. You normally check response.ok yourself.

POST with Fetch

const response = await fetch("/api/users", {
  method: "POST",
  headers: {
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    name: "Omkar",
    email: "omkar@example.com"
  })
});

if (!response.ok) {
  throw new Error("Request failed");
}

const user = await response.json();

Fetch Error Handling

async function request() {
  try {
    const response = await fetch("/api/data");

    if (!response.ok) {
      throw new Error(
        `Request failed: ${response.status}`
      );
    }

    return await response.json();
  } catch (error) {
    console.error(error);
    throw error;
  }
}

The catch handles network/abort errors and errors you explicitly throw for unsuccessful HTTP responses.

3. Axios

Axios is an HTTP client library with conveniences such as interceptors, request configuration and automatic response transformations.

import axios from "axios";

const response = await axios.get("/api/users");

console.log(response.data);

Unlike raw fetch, Axios rejects its Promise by default for HTTP status codes outside its successful range.

Axios POST

const response = await axios.post("/api/users", {
  name: "Omkar",
  email: "omkar@example.com"
});

console.log(response.data);

Fetch vs Axios

FetchAxios
Built into modern browsers.Third-party library.
Need to check response.ok for HTTP errors.Rejects non-2xx/3xx responses by default.
Manual conventions for interceptors/reusable config.Built-in interceptors and convenient configuration.
No dependency.Extra dependency.
Interview answer: Neither is universally better. Fetch is native and sufficient for many apps; Axios can simplify cross-cutting HTTP concerns.

4. AbortController

AbortController lets you cancel an in-progress fetch request.

const controller = new AbortController();

fetch("/api/users", {
  signal: controller.signal
});

// Cancel it
controller.abort();

Cancellation is especially useful when a component unmounts or a newer request makes an older request unnecessary.

AbortController with useEffect

useEffect(() => {
  const controller = new AbortController();

  async function load() {
    try {
      const response = await fetch("/api/users", {
        signal: controller.signal
      });

      if (!response.ok) {
        throw new Error("Request failed");
      }

      const data = await response.json();
      setUsers(data);
    } catch (error) {
      if (error.name !== "AbortError") {
        setError(error);
      }
    }
  }

  load();

  return () => controller.abort();
}, []);
Cleanup aborts the request when the effect is cleaned up, helping avoid unnecessary work and stale responses.

5. Authentication

Authentication answers: "Who is this user?"

Authorization answers: "What is this user allowed to do?"

Login ↓ Credentials / OAuth ↓ Server verifies identity ↓ Session / token ↓ Authenticated requests ↓ Backend checks authorization ↓ Response

6. JWT

A JWT (JSON Web Token) is a signed token format commonly used to carry claims between parties.

eyJhbGciOiJIUzI1NiJ9.
eyJzdWIiOiIxMjMifQ.
signature

A JWT commonly has a header, payload and signature. The payload is not secret merely because it is encoded. Do not put sensitive secrets in it.

JWT Request Flow

Login ↓ Server issues token ↓ Client stores/uses credential ↓ Request Authorization: Bearer <token> ↓ Server verifies token ↓ Protected response

Where the credential is stored matters greatly for security. Avoid exposing sensitive long-lived tokens to JavaScript when an appropriately configured secure cookie-based session is possible.

7. Refresh Token

A refresh token is used to obtain a new access token after the short-lived access token expires.

Access token expires ↓ Client sends refresh request ↓ Server validates refresh credential ↓ New access token ↓ Retry original API request

Refresh-token designs vary. Secure applications typically use short-lived access tokens and carefully protect refresh credentials.

Access Token vs Refresh Token

Access TokenRefresh Token
Used frequently for API authorization.Used to obtain a new access token.
Usually shorter lifetime.Usually longer lifetime.
Sent to protected APIs.Should be sent only to the refresh endpoint.

8. Cookie Authentication

With cookie-based authentication, the browser stores a session credential in a cookie and sends it with matching requests.

Set-Cookie:
session=abc123;
HttpOnly;
Secure;
SameSite=Lax

HttpOnly prevents JavaScript from reading the cookie. Secure limits it to HTTPS. SameSite controls cross-site sending behavior.

Cookie security also requires CSRF considerations and appropriate server configuration.

9. OAuth

OAuth 2.0 is an authorization framework. It allows an application to obtain limited access to resources without sharing the user's password with the client application.

User ↓ Client App ↓ Authorization Server ↓ User grants permission ↓ Authorization code ↓ Token exchange ↓ Client accesses resource server

For browser/mobile applications, Authorization Code + PKCE is a common modern flow.

Authentication Storage — Interview View

ApproachMain concern
HttpOnly Secure cookieHelps protect credential from JavaScript access; requires CSRF-aware design.
localStorage tokenAccessible to JavaScript, so XSS can expose it.
sessionStorage tokenAlso accessible to JavaScript; lifetime differs from localStorage.

There is no single storage choice that solves all security problems. Threat model, backend architecture and cookie settings matter.

10. Axios Interceptors

Interceptors can run logic before a request or after a response.

const api = axios.create({
  baseURL: "/api"
});

api.interceptors.request.use(config => {
  // add common request configuration
  return config;
});

api.interceptors.response.use(
  response => response,
  error => {
    // central error handling
    return Promise.reject(error);
  }
);

Common uses include common headers, logging and authentication flows.

11. Error Handling

Handle errors at the right level.

Request ↓ Network error? → Retry / offline UI ↓ HTTP error? ├─ 401 → authenticate/refresh/session handling ├─ 403 → not authorized ├─ 404 → resource not found ├─ 429 → rate limit/backoff └─ 5xx → server issue / retry when safe ↓ Validation error → show field/message

HTTP Error Handling Example

async function getUser(id) {
  const response = await fetch(`/api/users/${id}`);

  if (response.status === 404) {
    throw new Error("User not found");
  }

  if (!response.ok) {
    throw new Error("Server error");
  }

  return response.json();
}

For production apps, create structured application errors instead of relying only on generic strings.

12. Retry

Retry means attempting a failed request again. Retries should be deliberate, not automatic for every error.

Request fails ↓ Is retry safe? ↓ Transient error? ↓ yes Wait with backoff ↓ Retry ↓ Stop after limit

Retries are generally more appropriate for transient network/server failures than for permanent 4xx errors.

Exponential Backoff

delay = baseDelay * 2^attempt

Attempt 0 → 1x
Attempt 1 → 2x
Attempt 2 → 4x
Attempt 3 → 8x

Real systems often add jitter so many clients do not retry at exactly the same time.

Retry Example

async function retry(fn, maxRetries = 3) {
  let attempt = 0;

  while (true) {
    try {
      return await fn();
    } catch (error) {
      if (attempt >= maxRetries) {
        throw error;
      }

      const delay =
        500 * 2 ** attempt +
        Math.random() * 200;

      await new Promise(resolve =>
        setTimeout(resolve, delay)
      );

      attempt++;
    }
  }
}

Production retry logic should classify errors and respect request idempotency.

13. Pagination

Pagination divides a large result set into smaller pages.

GET /api/products?page=2&limit=20
Page 1 → items 1–20 Page 2 → items 21–40 Page 3 → items 41–60

It reduces the amount of data returned and rendered at once.

Offset vs Cursor Pagination

OffsetCursor
?page=10&limit=20?cursor=abc123&limit=20
Simple to understand.Better suited to changing/large datasets in many cases.
Can become expensive/inconsistent at large offsets.Uses a position/token from the previous result.

Pagination Example

async function getProducts(page) {
  const response = await fetch(
    `/api/products?page=${page}&limit=20`
  );

  if (!response.ok) {
    throw new Error("Failed");
  }

  return response.json();
}

14. Infinite Scroll

Infinite scroll automatically loads another page when the user approaches the end of the current list.

Initial page ↓ User scrolls ↓ Near bottom? ↓ yes Fetch next page ↓ Append items ↓ Repeat

Intersection Observer is often better than listening to every scroll event.

Infinite Scroll with IntersectionObserver

const observer = new IntersectionObserver(entries => {
  if (entries[0].isIntersecting) {
    loadNextPage();
  }
});

observer.observe(sentinelElement);

The sentinel is usually a small element placed after the last item.

15. Pagination + Infinite Scroll + Virtualization

Backend pagination ↓ Fetch pages ↓ Infinite scroll ↓ Large accumulated list ↓ Virtualization ↓ Only visible rows rendered

These solve different problems: pagination limits transferred data, infinite scroll controls when pages are requested, and virtualization limits rendered DOM nodes.

16. Race Conditions

Suppose a user searches "rea" and then quickly searches "react". The older request may finish after the newer request and overwrite the correct result.

Search "rea" → Request A ───────→ response A Search "react" → Request B → response B If A finishes last: ❌ old result overwrites new result Solution: Abort A / ignore stale A

Use AbortController, request IDs or a server-state library that handles query identity/cancellation appropriately.

17. API Layer Best Practices

  • Keep API calls out of random UI code when possible; create reusable API functions/services.
  • Centralize common base URL and headers.
  • Handle authentication consistently.
  • Normalize/validate response data where needed.
  • Cancel obsolete requests.
  • Handle loading, empty and error states.
  • Retry only safe/transient failures.
  • Use pagination for large datasets.
  • Use server-state caching when appropriate.
  • Never trust client-side authorization.

Most Asked Interview Questions

  1. Fetch vs Axios? Fetch is built into browsers; Axios is a library with conveniences such as interceptors and different default error behavior.
  2. Does fetch reject on 404? No. It normally resolves with a Response, so check response.ok/status.
  3. Why use AbortController? To cancel in-progress fetch requests, especially obsolete or unmounted requests.
  4. What is JWT? A signed token format containing claims; its payload is encoded, not automatically encrypted.
  5. Access token vs refresh token? Access token authorizes API requests and is usually short-lived; refresh token obtains a new access token.
  6. What is OAuth? An authorization framework that allows delegated access without giving the client the user's password.
  7. What is a cookie-based session? The browser sends a session credential in a cookie with matching requests.
  8. What does HttpOnly do? Prevents JavaScript from reading the cookie.
  9. What does Secure do? Restricts cookie transmission to HTTPS.
  10. What is SameSite? A cookie attribute controlling cross-site sending behavior.
  11. What is retry with exponential backoff? Reattempting transient failures with progressively longer delays.
  12. Should every API error be retried? No. Retry only suitable transient failures and consider idempotency/rate limits.
  13. What is pagination? Dividing large datasets into smaller result pages.
  14. Offset vs cursor pagination? Offset uses page/offset positions; cursor uses a continuation token/position and is often better for changing large datasets.
  15. What is infinite scroll? Automatically loading additional pages as the user approaches the end of a list.
  16. Why use IntersectionObserver? It can detect when a sentinel approaches the viewport without manually processing every scroll event.
  17. How do you handle API race conditions? Cancel obsolete requests or ensure stale responses cannot overwrite newer results.
  18. Where should authentication be enforced? On the server/API; frontend guards are only a UX/navigation layer.
  19. What status code represents unauthorized authentication? Commonly 401 for missing/invalid authentication; 403 is commonly used when the identity is known but access is forbidden.

Scenario-Based Questions

  1. fetch returns 404 but catch does not run.
    Check response.ok/status and throw your own application error if needed.
  2. A component unmounts while a fetch is running.
    Use AbortController in the effect cleanup to cancel the request.
  3. Search results show old data after a fast second search.
    Abort the older request or ignore responses that are no longer current.
  4. The server returns 500 temporarily.
    Retry with a bounded exponential backoff if the request is safe to retry.
  5. A POST failed due to a validation error.
    Do not blindly retry; show the validation error and let the user correct it.
  6. A GET request gets rate-limited with 429.
    Respect Retry-After when provided and use controlled backoff.
  7. You have 100,000 users in the database.
    Do not return all users. Use pagination, filtering and appropriate server-side indexing.
  8. Users can sort/filter a paginated table.
    Include sorting/filter values in the API request and reset pagination appropriately when the query changes.
  9. A feed should load more when the user reaches the bottom.
    Use paginated API requests with an IntersectionObserver sentinel.
  10. Infinite scroll repeatedly requests the same page.
    Track loading state and the next cursor/page; prevent duplicate next-page requests.
  11. A list has thousands of accumulated items.
    Combine pagination/infinite loading with virtualization if rendering all accumulated items becomes expensive.
  12. You need login persistence without exposing a long-lived credential to JavaScript.
    Consider a secure HttpOnly cookie-based session/refresh design with appropriate CSRF protection.
  13. A JWT payload contains a password.
    Never do this. JWT payloads are readable when encoded; secrets must not be placed in them.
  14. A user can access /admin in the UI by changing the URL.
    Frontend routing is not security. The backend must verify authorization for every protected operation.
  15. Multiple components need the same API data.
    Consider a server-state cache such as TanStack Query or RTK Query to avoid duplicated fetching and coordinate cache updates.
