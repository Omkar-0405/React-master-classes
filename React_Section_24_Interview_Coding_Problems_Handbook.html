Section 24 — React Interview Coding Problems

Simple Coding Handbook • 25 Frequently Asked React UI Problems

1. How to Approach a React Coding Interview

Understand requirements ↓ Break UI into components ↓ Identify state ↓ Define events/data flow ↓ Build simple version ↓ Handle edge cases ↓ Improve performance

Do not immediately write code. Spend a few minutes explaining the state, component structure and edge cases first.

2. Coding Checklist

  • What are the components?
  • What state is required?
  • Who owns each state?
  • What happens on user action?
  • What are loading/error/empty states?
  • What happens with empty input?
  • What happens with duplicate data?
  • Can stale requests create bugs?
  • Does the list need virtualization/pagination?
  • Can the solution be made reusable?

3. Todo App

Requirements: Add, complete, delete and filter todos.

TodoApp ├── TodoInput ├── TodoFilters └── TodoList └── TodoItem 
const [todos, setTodos] = useState([]);

function addTodo(text) {
  setTodos(prev => [
    ...prev,
    {
      id: crypto.randomUUID(),
      text,
      completed: false
    }
  ]);
}

function toggleTodo(id) {
  setTodos(prev =>
    prev.map(todo =>
      todo.id === id
        ? { ...todo, completed: !todo.completed }
        : todo
    )
  );
}

Interview focus: immutable updates, stable IDs and derived filtering.

const lastItemRef = node => {

11. Debounce Search

Debounce waits until the user stops typing before running an action.

function useDebounce(value, delay) {
  const [debounced, setDebounced] =
    useState(value);

  useEffect(() => {
    const id = setTimeout(
      () => setDebounced(value),
      delay
    );

    return () => clearTimeout(id);
  }, [value, delay]);

  return debounced;
}

18. Shopping Cart

const [cart, setCart] = useState([]);

function addToCart(product) {
  setCart(prev => {
    const existing =
      prev.find(x => x.id === product.id);

    if (existing) {
      return prev.map(x =>
        x.id === product.id
          ? { ...x, qty: x.qty + 1 }
          : x
      );
    }

    return [...prev, { ...product, qty: 1 }];
  });
}

const total = cart.reduce(

);

25. OTP Input

Usually use one controlled value or an array of digits and move focus automatically.

const refs = useRef([]);

function handleChange(index, value) {
  const digit = value.slice(-1);

  setOtp(prev => {
    const next = [...prev];
    next[index] = digit;
    return next;
  });

  if (digit) {
    refs.current[index + 1]?.focus();
  }
}

Also handle Backspace, paste, numeric input and accessibility.

30. Coding Interview Performance Rules

  • Use functional state updates when the next state depends on previous state.
  • Never mutate React state directly.
  • Use stable keys for dynamic lists.
  • Clean up timers, listeners and observers.
  • Handle async race conditions.
  • Disable duplicate submissions when necessary.
  • Keep derived values derived instead of duplicating state.
  • Extract reusable logic into hooks when it improves clarity.
  • Do not optimize before identifying a real bottleneck.
  • Explain trade-offs while coding.

31. Scenario-Based Questions

  1. Your typeahead shows results for an older query after a newer query.
    Cancel the previous request with AbortController or track request IDs and ignore stale responses.
  2. Infinite scroll fires five requests at once.
    Guard with an in-flight flag/query state and only request the next page when the current request is settled.
  3. A modal traps the user behind it.
    Implement focus management, Escape handling and proper modal semantics; restore focus when it closes.
  4. A 10,000-item list is slow.
    Use virtualization so only visible rows are rendered.
  5. A Kanban API rejects an optimistic move.
    Rollback the local move and show a clear error.
  6. A tree has 50,000 nodes.
    Do not render the entire tree blindly; lazy-load children and consider virtualization/efficient expansion state.
  7. A form has 100 fields and becomes difficult to maintain.
    Use a schema-driven field registry and reusable field components instead of a giant conditional component.
  8. A user double-clicks Submit and creates two orders.
    Disable or guard duplicate submission and use server-side idempotency for critical operations.
  9. A shopping cart total is wrong after quantity changes.
    Keep the item state as the source of truth and derive the total from the current cart rather than storing a separately mutable total.
  10. A multi-select re-renders the whole application.
    Keep selection state local if possible and inspect unnecessary parent renders before adding memoization.
  11. An OTP component loses focus after typing.
    Store input refs and move focus deliberately after a valid digit while handling paste and backspace.
  12. A calendar shows the wrong day around midnight.
    Review timezone/date-only handling and avoid accidental conversion between local time and UTC for date-only values.
  13. A file upload is 500 MB.
    Do not load the entire file into memory unnecessarily; use streaming/chunked upload where supported and show progress/cancellation.
  14. A carousel is inaccessible by keyboard.
    Add keyboard controls, focusable controls, accessible labels and respect reduced-motion preferences.
  15. A data table has millions of records.
    Use server-side filtering/sorting/pagination or cursors and virtualize the visible rows rather than loading everything into the browser.
